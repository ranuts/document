# 首页与落地页去卡片化（2026-08-22）

## 起因

用户看首页的判断：「卡片太多了」。数了一下确实——首页一屏往下走，是 7 张格式卡片 +
4 张 bento 特性卡片 + hero 里一个带边框的自动保存说明，再加 20 多个 SEO 落地页各自
带一张 `r-card.oss`。每张卡片都是"圆角 + 边框 + 内边距"，读一句话要先解析一个容器，
十一个容器叠在一起，页面就变成一面圆角矩形墙。

## 做了什么

一句话：把"容器"换成"排版"。同样的信息层级，改用细线、栏、单色小标签表达。

| 区块                     | 之前                               | 之后                                                                                    |
| ------------------------ | ---------------------------------- | --------------------------------------------------------------------------------------- |
| 首页「打开文件」         | 4 列卡片网格，7 项排成 4+3 的残行  | `.index` 单列索引表：扩展名 / 动作 / 说明 / 箭头四列，每行一条 hairline，hover 整行点亮 |
| 首页「隐私是设计出来的」 | 4 张 bento 卡片（`a a b / c d d`） | `.pillars` 报纸分栏：列间 1px 竖线，`subgrid` 让标签/标题/正文三行跨列对齐              |
| hero 自动保存说明        | 填充底色 + hairline 外框           | 左侧 2px 竖线的旁注                                                                     |
| 20+ 落地页的开源声明     | `<r-card class="oss">`             | `<aside class="oss">`，同样的左竖线旁注                                                 |

顺带（同一处版面的节奏问题）：

- hero 右侧的"文档窗口"从 348px 加高到 451px（骨架行 + 一个二级标题条），并把 hero 的
  下内边距从 96px 收到 56px——右列此前像一枚小卡片贴在 700px 高的文案旁边，下面空一大片。
- FAQ 左栏（原本只有一个标题，右侧四条问答）补一句指向 `/help` 的说明，填掉那块空白。
- 首页与所有落地页不再引用 `/ranui-iife/card.iife.js`（`bin/build-pages.mjs` 的生成模板
  也一并去掉），少一个组件包。仍在用 `r-card` 的只剩 `public/embed-demo.html` 的日志面板
  ——那是真正的应用面板，卡片语义正确，保留。

## 为什么行式索引比卡片网格合适

七个入口是**一份目录**，不是七个并列的产品：同样的动词、同样的结构，读者是沿着左边缘
往下扫、找自己的扩展名。卡片网格把这个一维扫描变成二维，而且 7 不被 4 整除，最后一行
永远缺口。行式布局一行一条 hairline，扩展名固定在左列，扫起来是一条直线。

响应式分三档：≤980 收紧列宽、≤760 去掉描述列（扩展名和动作才是查找依据）、
≤560 扩展名折到标题上方、箭头竖跨两行。

## 为什么 pillars 要 subgrid

四条主张的标题长短不一（"Files never leave your device" 两行，"Nothing to sign up for"
一行）。去掉卡片以后没有容器兜底，正文的基线就参差了——这正是"没有框看起来没做完"的
来源。`grid-template-rows: subgrid` 让四列共享标签/标题/正文三行，标题占两行时四列一起占
两行，正文永远齐平。

## 验证

- `pnpm vitest run test/unit/design-contract.test.ts test/unit/landing-pages.test.ts test/unit/generated-pages.test.ts` 全绿（宽度契约、SEO 落地页契约、生成页新鲜度）。
- 视觉：1440 / 834 / 390 三档 + 暗色，逐页看过截图。
- 首页元素契约未动：`#hero-open`、`#hero-new-*`、`[data-prefetch]`、`[data-recent-slot]`
  都还在原处（E2E `main-site` / `app-smoke` / `save-to-file` / `autosave-recovery` 依赖它们）。

## 没做的

- `/help` 的目录框、`/embed-demo` 的日志面板：都是应用型面板，不属于"内容被装进卡片"。
- `.eco` 那两个生态链接 pill：它们是链接，不是内容容器。

## 追加：内容页在宽屏上加了一条目录栏（同日）

去掉卡片之后，用户在 1600 宽的窗口里看 `/open/docx`，问的是"内容区域是不是太窄了"。
量了一下：**行宽没问题，页面结构才是问题**。

`node bin/design-audit.mjs` 当时给出的是落地页 66 字符——Bringhurst 的理想值 66，
45–75 区间的正中。窄的不是文字，是整页只有一根 720 的柱子：1600 视口下正文占 45%，
两侧各空 440px，而且右边什么都没有。

三种业界做法，区别在于"这个页面有几件事要做"：

- 纯阅读（Substack、Medium）：单柱 620–740，两侧就是空的。页面只有"读"一件事。
- 文档 / 帮助（Stripe Docs、Vercel Docs、MDN）：版心 1200–1440，正文 680–760 **不变**，
  两侧放导航与 On this page。宽屏不空是靠功能栏，不是靠加宽正文。
- 营销落地页（Vercel、Linear）：版心 1200–1280，段落仍 60–70ch，靠窄正文与全宽视觉带交替。

`/open/*` 这类页是"营销 + 文档"的混合（h1 + CTA + 说明 + 步骤 + 清单 + 7 条 FAQ，
读者会跳着找 FAQ，而 CTA 滚过首屏就消失），所以取第二种。

### 落到实现

- `landing.css .page`：`≥1081px` 时 `grid-template-columns: minmax(0,660px) minmax(0,284px)`，
  外框 1152，`justify-content: center`。
- **正文列是 660 而不是 720**。这是这次唯一容易搞错的地方：旧版"720 容器"里有
  56px 的左右内边距，文本宽其实是 608px / 66 字符。直接把 720 交给列，
  行宽会变成 **77 字符**——比改之前更难读。660 落在 72，与首页同值。
  第一版就是这么错的，`bin/design-audit.mjs` 一跑就看出来了。
- 右栏 `.side`：常驻 CTA（复用页面自己的那个 `<a class="cta">`，文案不重写）、
  本页目录（h2 锚点，脚本给每个 h2 补了 slug id）、相关页面（从页面自己的 footer 里
  取，同目录优先，所以 `/open/docx` 推的是其它格式而不是 Embed API；标签天然本地化）。
- `<1081px` 直接 `display: none`：手机上 CTA 本就在首屏，目录只会挡在读者和正文之间。
- 页脚移出 `<main>`，`.page-foot` 铺满 1152。
- `/help` 与 `/changelog` 走同一套（改 `bin/build-pages.mjs` 的 shell）：
  原来顶在正文最上方的那个 `.toc` 框搬进右栏——`/help` 有 9 个 section，
  那是 9 行链接横在读者和第一句话之间。`.doc .toc` 的样式一并删掉，没有别的页面用。
  右栏在 `/help` 上会长过视口，所以 `max-height: calc(100vh - space-16) + overflow-y: auto`。
- 右栏 CTA 是 `width: 100%` 的 pill，**宽度必须同时给到 `::part(button)` 与 `::part(content)`**，
  否则 host 画的矩形阴影会从圆角两端露出来一条直线（首页 CTA 踩过同一个坑）。

### 钉住

- `design-contract`：`.page` 外框必须是 1152，正文列必须落在 600–680（防止有人"顺手"改回 720）。
- `landing-pages`：每个内容页必须有 `<aside class="side">` 与 CTA，且右栏里的锚点
  与页面 h2 一一对应。**反向验证做过**：删掉 `/open/pdf` 的 `<aside>` 后该用例变红，
  恢复后转绿；把 1152 断言改成 9999 后 design-contract 变红。

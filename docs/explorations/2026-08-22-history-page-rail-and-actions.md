# /history：去掉最后一处卡片，补上真正缺的动作（2026-08-22）

## 起因

用户看线上 https://edit.chaxus.com/history 后问"怎么做得更好"。喂了 7 条测试记录
（本机 IndexedDB，不入库）之后，问题一次看清：

**版式**——列表是一个大卡片，底部"自动保存 / 全部删除 / 7 天规则"又是一个填色卡片。
刚把全站的卡片换成细线，这页是唯一还留着的。扩展名徽章、`not exported` 标签也都是小胶囊，
一行里三个盒子。

**交互**——每行只有 Delete。而人打开这个页面的典型原因是"有份没导出的东西要拿出来"，
当时唯一的路径是打开编辑器再 Ctrl+S。7 行就有 7 个常驻的 Delete，是页面上最显眼的重复元素，
而它不可逆。倒计时里 `7 days left` 和 `1 day left` 长得一模一样，而后者是这页唯一有时间压力的信息。
只有搜索，没有"只看未导出"——未导出的那几份才是真正会丢的。

## 改了什么

1. **框架换成 1152 两栏**（`history.css .history-shell`）：列表列 660，右栏 284 放存储用量、
   自动保存开关、全部删除、保留规则。列表只剩文档本身。
2. **列表去卡片**：每行一条 hairline，hover 整行点亮（与首页格式索引同一套语言）；
   扩展名从胶囊徽章改成 mono 文本。
3. **每行加「下载副本」**：`getLatestSnapshot()` 拿字节，`ranuts` 的 `saveFileToDisk` 写盘
   （有 File System Access 就走"另存为"，否则下载）。
4. **到期分级**：≤1 天用 warning 色。
5. **「只看未导出」筛选**：`listDocs({ unsavedOnly })`，状态进 URL（`?unsaved=1`）。
6. **空状态**给「打开文件」而不是「返回首页」：这页刻意不加载编辑器 bundle，所以走
   `lib/pending-open.ts` 的 IndexedDB 交接（新增 `stashPendingFile`，与 `public/open-local.js` 同一套 DB/store/key）。

## 三个不显然的决定

**下载不等于导出。** `downloadDoc` 刻意不调 `markSavedToDisk`：写到盘上的是最后一份自动保存的
快照，不一定等于编辑器此刻会产出的内容。把它记成"已导出"会把"这份工作只有这一个副本"的提示
灭掉，而那个提示正是这个列表存在的理由。E2E 钉住：下载之后 `.history-badge` 仍在。

**筛选在 store 层，不在页面层。** `listDocs` 里过滤，`total` 与页数才描述用户真正在看的列表；
在页面层过滤会得到"按未过滤总数分页"的空页。

**右栏在窄屏不隐藏。** 内容页的右栏（`landing.css .side`）在 <1081px 直接 `display:none`——
那是导航，手机上只会挡路。`/history` 的右栏是**控件**（自动保存开关、全部删除），
所以它落到列表下方，也就是它原本待的位置。同一个视觉模式，两条相反的响应式规则，
理由是里面装的东西不同。

顺带：手机上行的布局改了。原来的注释写着"手机上保持一行，让标题省略号"——那是只有一个
Delete 时的正确取舍；Download 一并列上去之后，390px 宽的行里文件名被压到 `Q3 r...`。
现在两个动作换到第二行右对齐，文件名完整。

## 验证

- 新增 4 条 E2E（`test/e2e/history-page.spec.ts`）：下载写盘且徽章不变、未导出筛选（含 URL 往返）、
  最后一天与其它事实不同色、空状态给的是文件选择器。**反向验证做过**：同时去掉四处实现后，
  正好这 4 条红、其余 11 条绿；恢复后 15 条全绿。
- `design-contract` 现在对内容页与 `/history` 用同一条参数化断言（框架 1152、列 600–680）。
  把 `.history-shell` 改回 720 会让两条用例红。
- `bin/design-audit.mjs`：`/history` 行宽 69 字符，在 45–75 内。
- 1440 / 390 / 暗色逐一看过。

## 一个未解的观察

`pnpm run dev` 下 `/history` 白屏：模块被请求了，但 `history-page.ts` 从未执行，
控制台只有一条 `/@vite/client` 404（同一个 URL `curl` 是 200）。生产构建与 `vite preview`
下一切正常，E2E 也全绿，所以本轮是用 `vite build && vite preview` 迭代的。
影响的是开发体验而不是线上，单独查。

# Assistant workspace owners

The panel composes existing inference and document-review lifecycles with two independent features. A model service is an execution destination, a local reference is an explicitly selected file, and an artifact is an explicitly saved result. None creates a site account. External account connectors and the external-service MCP client were removed to keep the editor account-free and statically deployable; see the [MCP investigation and product decision](../explorations/2026-10-18-mcp-connectors-and-frontend-boundaries.md).

## Sources

`references/reference-sources.ts` owns immutable local reference snapshots and per-conversation attachment sets. Local references support `.txt`, `.md`, `.csv`, `.tsv` and `.json` up to 256 KiB, plus standalone DOCX, XLSX, PPTX and text-bearing PDF readers with 20 MiB input and 256 KiB extracted-text limits. These local readers do not replace or mutate the open document. OOXML extraction bounds archives to 2,000 entries, 32 MiB cumulative inflation and 100,000 XML elements, with 10,000 paragraphs or 10,000 cells across 20 sheets; PDF extraction allows 100 pages. All extraction has a 15-second deadline; scanned images require OCR, which is not provided. See [reference limits](../reference.md) for format and offline requirements. Up to five attachments are selected explicitly. Attachments remain in memory and are not silently restored from disk.

`ui/sources-view.ts` owns local file attachment, removal, search and read-only preview. Attachment capacity errors identify the five-source limit. Local reads have byte limits and deadlines; epoch checks prevent late reads from entering another conversation. `panel.ts` captures selected references at enqueue, guards them before execution and continuation, and cancels execution when its attachments are invalidated. Adding another attachment cannot change an already queued snapshot.

`references/reference-search.ts` owns literal local filtering and query-centered excerpt windows. Source disclosures show up to 8,000 characters, highlight the actual match and label partial previews. Expanding a source or a captured citation never fetches content or starts inference.

`ui/request-context.ts` creates bounded JSON excerpts with controlled ids S1–S5, source titles, source-kind metadata and truncation flags. Host locators stay outside the model payload. It returns the exact serialized evidence, and native/ordinary-chat routes publish their final serialization before streaming. The runtime reports any additional clipping before each inference. `ui/source-evidence.ts` reconciles this with the immutable captured snapshot. `ui/source-citations.ts` decorates only matching literal citations using text-only captured excerpts; unknown ids remain plain text and original Copy/Save content is unchanged.

Each inference response can carry a host-minted stable `hostPresentation.id` with bounded presentation metadata, attached directly to that response rather than matched by prose or history index. The runtime strips the annotation before all provider calls. Conversation opt-in is still required for persistence; removing a conversation removes its annotations. Only the bounded excerpts actually sent are retained, never the full attachment. Restored legacy responses without annotations do not invent citations. Instruction and existing request-envelope headroom are reserved. Native requests, conversational requests, document drafting and dedicated writing routes receive quoted reference data through their existing owners. Reference content never adds tool definitions or bypasses host review. The historical `connector` metadata field remains readable in saved conversations and artifact provenance; it does not restore a remote connection.

The service worker bypasses `/api/` requests rather than caching them as offline pages. No connector API, OAuth callback or Functions routing configuration is shipped. The editor's outbound WebMCP tool exposure remains independent from reference-file attachment.

## Artifacts

`artifacts/store.ts` owns a separate IndexedDB database with artifact bodies and metadata-only list summaries. Saving is explicit; conversation-history opt-in does not implicitly save results. A store holds at most 50 artifacts, 20 versions each and 128 KiB UTF-8 per version. Limits reject with a visible recovery message; existing versions are never silently pruned.

Updates check the expected version inside the same read-write transaction that appends the new version. Concurrent editors cannot overwrite one another. Selecting an older version and saving creates a new version. Deletion requires an explicit UI confirmation. Failed saves preserve editable drafts. Capacity errors distinguish artifact count, text size and version history. At 20 versions, an explicit save-as-new action preserves the draft and source provenance in a separate artifact without modifying existing history.

`ui/artifacts-view.ts` owns local text editing, version selection and conflict presentation. The generic chat package provides an optional host save action with opaque, render-time provenance. It does not know IndexedDB or reference storage. Source titles and conversation identity are captured with live results; old restored results with no retained source metadata do not invent source provenance.

`artifacts/edit-proposal.ts` owns immutable draft identity, title/body/revision freshness and native UTF-16 selection offsets. A collapsed selection means the complete artifact; selecting a range sends and replaces only that range. `ui/artifact-workflow.ts` owns a single disclosed instruction, bounded streaming preview and explicit diff acceptance. Accepting updates the editable draft only; Save version remains separate. Default previews show at most 8,000 characters; expanding the complete diff is explicit. Stop, rejection and failures keep the instruction and draft. A quiet scope line distinguishes selected text from the entire artifact before submission. Queue recovery routes instructions back to artifact refinement, never through the Office chat composer. If a restored selection belonged to an older body, a fresh selection or explicit entire-artifact choice is required; old offsets are not reused.

`ui/artifact-request.ts` dispatches through the panel's existing global request queue before any Office capture, classifier or controller. It uses only the selected, already prepared provider with no tool definitions or automatic connection/download/fallback. Captured attached references use the existing bounded request serializer. Document and artifact requests cannot run models concurrently; cancelling a queued artifact removes only its entry, and stopping active inference holds the global lease until the provider physically settles. Draft/title/version/navigation, source, conversation and provider changes invalidate a proposal. Persisted versions and current draft/context guards are checked before and after inference and again after the asynchronous acceptance read. A concurrent save or version cap offers explicit Save as new, preserving the current draft/title and original creation provenance without overwriting the newer artifact.

Applying an artifact captures a fresh Word target and creates the existing `ActionPreview`; nothing writes until the user confirms that preview. Queue application leases, target freshness, host verification and native Undo remain the existing owners. The artifact editor never executes generated code or renders arbitrary HTML.

## Offline availability

Offline mode hides the downloadable model catalog and remote model URLs. It retains attached reference snapshots, local file attachment, saved artifact editing and versions, cached model management, local GGUF files, and local or LAN model services. Existing model configuration remains inspectable. Connectivity restoration only restores controls; it never downloads, reconnects or resends automatically. Browser connectivity is a presentation signal; actual request failures still receive actionable recovery messages.

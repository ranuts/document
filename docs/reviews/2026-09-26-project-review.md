## 性能与页面质量

- 本地桌面、无 CPU / 网络节流的首页 reload trace：LCP 约 270 ms，CLS 0。
  这是实验室观察，不代表生产网络或真实用户分位数；没有测量交互 INP。
- 首页未请求 `/assets/` 下的编辑器和 AI 应用 bundle；重型编辑器资源通过后台预热加载。
- 首轮 Lighthouse snapshot 找到一项语言按钮名称问题。修复后 Accessibility、
  Best Practices、SEO、Agentic Browsing 均为 100，33 项通过，0 项失败。
  此 snapshot 不包含 Lighthouse 性能评分。
- 当前 vendor 目录占用约 SDK 125 MB、字体 184 MB、web-apps 141 MB。
  这些是文件系统体积，不是首次访问传输量。最大应用 JS 块约 5.7 MiB，
  属于按需加载的 WebLLM 运行时。后续体积工作应基于实际格式和字体请求统计确定范围。
- 本地已打开的 DOCX 在模拟断网后可重新加载；未缓存资源、未使用的格式、
  远程文件和其他浏览器的离线行为仍需各自验证。

## 验证结果

- 单元测试：60 个文件、3462 项通过。包含实际运行 worker 与 vendor helper 的边界测试。
- 相关 Chromium E2E：52 项通过，覆盖嵌入 API、DOCX / XLSX / PPTX 插图与导出、
  CSV / PDF、文件写回、语言菜单、版权入口及 PWA 图标。
- TypeScript / oxlint、Prettier、生产构建、`git diff --check` 通过。
- 安全、缓存和标题回归均先复现失败，再验证修复。

项目测试范围更大；本轮未执行完整 E2E corpus / API sweep，也未验证所有浏览器。
构建仍提示可选 Anthropic SDK 的 Node 模块浏览器外部化和较大的 WebLLM chunk；
单元测试仍有原有 `PromiseRejectionHandledWarning`。这些不影响本轮通过的验证，
但不能据此断言所有供应商和设备组合都已验证。

## 集成注意事项

嵌入命令只由直接父窗口发送；父窗口来源改变后应重新加载编辑器建立通信。
宿主使用正式的 `document:save` / `document:saved` 接口获取文件，决定后续上传。
原来由顶层页面直接监听底层文件流的测试路径已迁移到直接宿主。

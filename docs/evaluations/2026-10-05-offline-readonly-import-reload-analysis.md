Current production422b49e, previously warmed owned Chromium profile, browser offline before navigation. Actual Home picker imported the saved DOCX; native full API was ready and native text exactly `WEBKIT_WORD_20261005\r\n`. Its address was stamped `?saved=<id>`. A direct IndexedDB read found no docs row under that exact id. Navigating that saved URL with explicit agent opt-in ended at Home, with zero editor iframes and no page errors. This diagnostic exits nonzero if these observations differ and closes the context. Report independently verified.

This explains the prior90-second editor-ready timeout without guessing about offline models or WASM. `lib/history/session.ts` explicitly stamps the identity before any snapshot exists and says reading alone leaves no row. `lib/history/autosave.ts` takes snapshots only when dirty. `index.ts` first attempts saved-record restoration, then sends a bare saved id without any stored document back to Home. The observed null row and real redirect match those branches. Adding agent opt-in is incidental to the reload; no model inference or startup is required to explain its missing iframe.

The local import itself succeeded. This is not proof that every saved-document reload fails, that changed/snapshotted files fail, or that offline cache registration/model startup is broken. The previously passing IM modification/Undo/Redo/Save chain remains valid within its explicit configuration. However, general local-file refresh recovery is not satisfied for this unedited-file path. A future implementation must retain a reloadable source for the active document while respecting the existing choice not to create document-history records merely for reading; blanket history snapshots or model changes would address a different problem. No recovery implementation is claimed here.

No production code changed. This single actual desktop Chromium/owned-cache characterization is not physical OS/mobile testing or broad semantic-quality acceptance. It narrows the next product action to active-document source recovery rather than a speculative engine workaround.

# CPU SDK input captured: context ordering does not solve compliance

The prior CPU experiment had no input capture and remains invalid. This corrected run instruments the actual native SDK createChatCompletion entry, with a required one-request capture assertion before interpreting any reply. It route-serves a diagnostic SDK asset and leaves dist bytes unchanged. Chromium CDP Network.setBypassServiceWorker was required for the interception: before bypass, the SDK appeared in resource entries but routeHits stayed empty; after bypass, the route hit and all eight SDK calls were captured. This supports Service Worker interception as the route-miss cause. The earlier claim that a different local-controller path necessarily bypassed runtime.ts was not established by empty capture and should not be treated as a root-cause finding.

Actual CPU Qwen3-0.6B, blank Word context, four known cases, one sample each in fixed current/request-first order, new conversation each. Captured native SDK settings were temperature 0, top_p 0.8, max_tokens 96 and stream true. System messages matched within every pair; only contextual user-content order changed. The real model template remains processed by the SDK.

English greeting stayed identical; Chinese greeting changed from 你好！祝你一切顺利。 to 您好！. Both arithmetic replies were 7 + 8 = 15, violating the requested number-only format. Both nonpayer replies were Mira. These observations provide no evidence that request-first ordering fixes the prior irrelevant editor-scope response or general fidelity. No adoption. The earlier exploratory CPU runs used different prompts/sampling and cannot be treated as controlled baselines.

No visible errors or preview cards; browser closed. No native document mutation/Save acceptance is claimed. Initial missing-capture and route-miss reports are preserved separately; they are harness failures, not model scores. The diagnostic only covers four simple known cases, not repeated reliability, document-bearing/multi-turn safety or multilingual writing acceptance. Run verify-cpu-sdk-chat-context-order.py for exact actual inputs and parameters. Next quality work should isolate system/sampling factors using this now-proven capture path rather than assuming an input change reached inference.

# Installed origin-down PWA: CPU IM edit, DOCX Save and reopen

A fresh headed Chromium 151 profile cached the application, Word editor and self-hosted Qwen2.5-0.5B Q4_K_M CPU model on an independently owned ephemeral origin. After native PWA installation, the seed browser closed and the whole serving origin was shut down; independent fetch failed. A new browser process launched the installed app and Word editor in standalone mode. The model URL was explicitly re-entered, cached CPU loading succeeded, and an actual greeting was generated. The bounded tools-mode IM command inserted `PWA_ORIGIN_DOWN_2026`; native Undo/Redo exactly restored blank/edited document text. No preview cards or IM errors were observed.

With the serving origin still unavailable, clicking the editor's existing native Save button produced a 25,851-byte DOCX through its download fallback. SHA-256: `103fee3702210c81e7c827e6f6490a0c65fe102a144e97984d77bf5929758b1a`. The same installed standalone window navigated to its cached homepage, opened the downloaded local file through the existing file chooser flow, and initialized the real Word engine. Reopened text was exactly `PWA_ORIGIN_DOWN_2026\r\n`, matching the edited/redo text. A separate Python ZIP/XML inspection verified the DOCX's `word/document.xml` contains the exact marker. The test application was uninstalled, final browser context closed and owned server remained shut down.

The final driver deliberately makes `showSaveFilePicker` unavailable in both contexts, selecting the application's existing download fallback. It does not simulate the conversion, download, file contents, Word engine or reopening. This proves the native Save button's download path; it does **not** prove the File System Access system picker path or overwrite-in-place behavior.

The preserved first driver/result timed out waiting for a download with the system picker API available. Native UI inspection could not proceed because Computer Use Accessibility/Screen Recording permissions were pending. No successful save is claimed from that first run, and the absence of a download event is not classified as a document-conversion failure. Its browser closed and test installation was removed before retry.

The successful run establishes installed desktop PWA cached CPU availability, bounded IM insertion, native history, offline-origin DOCX save-download and local-file reopen. The literal insertion follows existing deterministic tool grammar; it does not certify arbitrary model tool planning. The message-row `reply` includes its action label, not just generated text. Custom model URL restoration was manual. Physical full-network isolation, OS reboot/shortcut launch, mobile, GPU, semantic writing quality, cache eviction, broader formatting and Excel/PPT save parity remain open. Only the owned application/model origin was removed; no privacy claim is inferred for all other processes or destinations.

# Word unload property: pagehide migration spike

Product `77d0fd3` remains unchanged. The native editor frame registers an `onunload` property handler; a delegating addEventListener observer found no unload listener registrations in these two frames. Source inspection of the documenteditor main bundle identifies `onUnload` as clearing `continueSavingTimer`. Its preceding onBeforeUnload method can schedule that timer after stopping saving. The app already owns the beforeunload prompt through a separate guard. Both public and dist main bundles hash to `1ee2001a89af2ebe7a3714bdcd135faa5d6577626a5a7bb3e2c4aa3aa0645a88`; this is disk identity, not an independently hashed HTTP response.

A throwaway browser intervention captured the actual bound onunload function, cleared that property, and called the same function from pagehide. It did not replace the cleanup function or change checked-in product assets. Full Chromium then naturally stored/restored the page: pageshow persisted true and the original random instance token returned. The first probe stopped after a Playwright cached-subframe locator timeout; its DOM observation already showed the sidebar entry. That incomplete run is retained rather than treated as application failure or complete acceptance.

The follow-up ad-hoc driver uses the actual same-origin iframe DOM to inspect/click the native sidebar after cached restoration. Two real navigation/Back cycles passed. The instance token and unsent Chinese draft stayed identical; exactly one sidebar entry and resize handle returned each time, and closing/reopening via the native sidebar worked. The original handler call count was 1 then 2. No browser errors or cache rejection events were observed; the browser closed. Raw listener, interrupted-harness and completed reports/drivers are retained.

This supports the Word-specific migration hypothesis under a blank document/no-model scenario. It is not a production migration, a loaded-model return test, or proof of save-timer behavior with a populated timer. Excel and PPT unload responsibilities have not been audited here. Replacing all vendor unload handlers wholesale would be unsupported by this evidence. A formal repair must preserve actual teardown semantics, guard late vendor assignments, and verify save/download/native undo and the other document editors before broader acceptance. Physical mobile/offline/OS reboot requirements remain open.

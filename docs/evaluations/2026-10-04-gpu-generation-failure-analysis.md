# GPU generation failure recovery — 2026-10-04

The production lifecycle correctly settles an in-flight stream when a loaded GPU Worker encounters a controlled uncaught exception. It terminates the Worker, preserves native Word text and does not automatically replay the request through CPU. Explicit model Load creates a fresh GPU Worker and a newly submitted Hello request succeeds. No product change was made in this experiment.

The independent Playwright Chromium context uses the warm GPU profile, service workers blocked and network available. The Worker script response is captured, hashed and appended with a test-only message handler that throws. The actual model loads and produces more than 80 visible characters while the composer is disabled before the probe triggers that handler. The exception is a real Worker event path, not a synthetic owner-side ErrorEvent; it does not simulate physical GPU device loss, actual OOM or measure VRAM reclamation. SDK and application lifecycle listeners determine the error delivered to the host, so no pageerror is recorded in this run.

One streaming request is recorded before failure. The Worker is terminated once, no replacement/CPU Worker or additional completion request appears during the measured one-second wait. Word body remains empty and unchanged. On explicit Load a second GPU Worker is constructed; a second, independently submitted completion returns Hello. The probe binds the new assistant turn after retry rather than accepting an old reply. Later cleanup can call terminate multiple times, so those counts are API calls, not distinct Worker deaths.

The visible error is generic request-failed guidance with the existing Restore request action. It does not disclose the injected internal exception, but fails to tell the user that the model requires reloading. This is a concrete follow-up usability issue; recovery correctness does not imply error guidance is sufficient.

Independent read-only review found no Critical/Important evidence issue. Driver syntax, scoped verifier, Prettier and whitespace checks pass. The verifier binds exact executed driver bytes, request counts, Worker event order, no CPU replay, native text preservation and fresh reply. Captured Worker hashes describe the response body and injected body, not the full app provenance. No full product build/test repetition was required for an evidence-only probe. No forced offline, cold start, physical device/OOM, document task mutation, Save/reopen, partial-response retention or broad network/privacy acceptance. No claims about arbitrarily long waits beyond the observed interval. Owned process exited 0 and context closed.

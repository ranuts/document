# IM narrow-screen control sizing

Actual native Word editor screenshots showed a clear desktop side panel and no horizontal overflow at 390px, but primary icon buttons had small targets: settings/close 30px, new session 32px, quote 28px, send 34px. The narrow-screen stylesheet now gives these controls 44×44px boxes. New session also overrides its old 32px flex basis; an intermediate browser measurement caught that width constraint before final verification. Desktop sizing remains as observed.

Final production build passed. A fresh browser context measured 1280×900, 390×900, 390×400 and 320×400. All five specified controls actually measured 44×44px in every narrow viewport. No horizontal page overflow was observed; the input remained within the viewport in each case. The 390px settings scroll width equaled its client width. Screenshots were inspected for desktop, narrow settings and short/narrow composer presentation. Short windows retain the existing scrollable transcript area. The raw geometry is `2026-10-05-im-touch-layout.json`; two representative screenshots are retained alongside it.

`probe-im-touch-layout.mjs` is the ad-hoc QA driver copied after this run, not a preregistered model evaluation. Its outputs use the owned scratch directory. This CSS-only change was verified by production build and actual browser layout rather than DOM-only tests that cannot calculate CSS geometry. Whitespace checks passed. It does not prove on-device touch accuracy, virtual-keyboard behavior, screen-reader acceptance or mobile model compatibility. No preview or additional confirmation interface was added.

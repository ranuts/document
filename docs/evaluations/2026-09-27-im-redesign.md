# AI IM 界面重设计与验证

## 本轮范围

参考本机 Desktop/deepseek-harness 的工具摘要、工具树与会话/执行信息分层，沿用项目 ranui 主题、Geist 字体与无框架 ChatView 实现。桌面侧栏宽 400px；窄屏覆盖编辑器。无新增项目品牌。

- 用户消息右侧气泡，助手回答无气泡；移除角色标签，复制改为图标。
- Markdown 标题、列表、引用、代码和表格使用 DOM token 渲染；模型 HTML 不执行，图片不自动请求，链接限制为 http(s)/mailto。
- 工具名称/参数/输出及思考协议不进入回答；连续动作合并为默认折叠的人类可读摘要。活动仅代表调用发生，不表示成功。
- 输入区统一为问答/编辑/改写/摘要/翻译任务选择、语言、引用选区与发送/停止。修订模式、下载和缓存说明进入设置。
- 修改建议按时间出现在会话里，原文默认折叠；必须显式确认。后续建议保留前一张卡片及其已应用/失效状态。
- 模型只返回不可展示的协议且没有真正调用工具时，给出恢复请求的入口，不留下空白回答。
- 不改写有效持久化会话。加载时校验完整记录形状，损坏记录不进入界面或模型；底层存储不删除。

设计与执行记录见 `docs/superpowers/specs/2026-09-27-im-redesign-design.md`、`docs/superpowers/plans/2026-09-27-im-redesign.md`。

## 独立 review 的修正

1. 完成的 think 区后接分片工具 JSON，原实现可能短暂显示 JSON。现在先移除前导思考区，再决定是否暂存 JSON，加入回归测试。
2. 修改已发送但读回失败，不能展示普通重试提示。保留本地化的检查文档/撤销指导，防止重复应用。
3. 不再复用并移动同一张审阅卡片；旧卡片保留，旧待确认动作失效且按钮禁用。
4. 损坏会话形状验证同时保护展示和模型上下文。

## 真实模型兼容性补修

真实默认 Qwen3-1.7B WebLLM 问答在新会话中正常流式回答“你好！有什么可以帮助你的吗？”，界面未显示 think 或工具协议。但旧工具会话发生请求失败。独立直接复现确认 SDK 抛出字符串：`ContentTypeError: assistant's message should have string content.`

原因：历史工具调用转换为正文 null 的助手消息和 tool 角色，问答模型模板不接受。现在仅在没有活动工具的请求投影中，移除工具调用字段及正文 null 的消息，工具结果转换为明确标识的、JSON 引用的历史参考数据。有效原始会话不变；有活动工具的 Hermes 路径不变。

修复后真实模型带旧 get_selection/tool_result 历史成功回答“刚才选区里的预算是 1250 EUR。”，生成约1.95秒；不需要清空会话。界面展示投影仍移除前导 think 区。这是格式兼容验证，不是整体模型质量结论。

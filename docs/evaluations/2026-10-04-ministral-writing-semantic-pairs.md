# Ministral 3 3B browser writing diagnostic: loaded, not accepted

Actual custom model `Ministral-3-3B-Instruct-2512-BF16-q4f16_1-MLC` loads through WebLLM in the owned Chromium profile. Both the visible engine and each captured Worker request identify this model. Six previously committed semantic-pair rewrite fixtures run via the current Word IM writing route, temperature 0, bounded schema, current guards. The underlying production route chooses its model-specific prompt behavior; this is not an identical-token prompt ablation against Qwen. Raw-response recording and header isolation are route-local diagnostic instrumentation; no product source, default or dependency change.

All six results are refused and the native document stays unchanged. English payer samples produce meta-instructions or malformed amounts/dates rather than the requested formal rewrite. The two Chinese samples become repetitive, malformed text and end with stop reason `length`; these are incomplete responses, refused before application. Confirmation-required changes 640 to 640.10 and omits the stated date/name; confirmation-not-required changes 640 to 40, omits date/name and turns the task into an imperative. No preview cards or page errors. The test completes and closes its owned context.

Conclusion: this MLC model/runtime/prompt combination is unsuitable for adoption on this evidence. It demonstrates browser load success and rejection protection, not reliable rewriting. This does not prove the publisher's underlying model is intrinsically poor: compiled artifact correctness, tokenizer/template compatibility and bounded grammar interaction are not separately isolated. Do not reinterpret publisher benchmarks as local acceptance or replace the default merely because a newer catalog model loads.

Independent checks confirm fixture/driver identity, actual request model IDs, source/instruction payloads, six refusals and source preservation, and observed stop reasons. Separate HEAD probes for the catalog WASM and two tokenizer endpoints returned HTTP 200; this proves endpoint availability only, not fetched body integrity or successful use of every artifact. The initial load was allowed a bounded 600-second window; polling kept the same live process rather than restarting downloads. No measured load/download/VRAM budget is claimed.

Known six-case fixed-order single-run diagnostic only; not representative multilingual accuracy or model ranking. No native Save, cold/offline, physical-device or complete privacy/provenance certification. The record retains external request metadata; it is not an exhaustive network audit.

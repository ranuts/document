# Native CPU context overflow guidance

A real desktop Chromium CPU Qwen3-0.6B writing request selected 5,000 synthetic Chinese characters, within the application's 8,000-character selection limit. The pinned wllama native runtime measured 3,419 prompt tokens against its 2,048-token context and rejected the request. The previous UI displayed only generic failure. Exact original selected text remained unchanged; there was no preview card.

The provider now maps only the observed native inference_error and complete measured-token overflow message to the existing localized agentContextTooLong guidance. It does not infer token counts from characters, truncate document text, increase model memory, change generation/schema/guards, or add UI steps. Other failures retain their error object, including AbortError. The inference queue remains usable after failure.

After building, the actual UI displayed “This request is too long. Select a shorter passage or split the task.” The document remained exact. Restore request filled the original Chinese instruction without adding a user turn or executing a request. After manually replacing the isolated fixture with a short document and submitting an ordinary chat request, the model returned Hello. No additional visible error or page error was observed; preview count remained zero. Baseline and corrected runtime reports are archived separately. This is context-rejection/recovery evidence, not general writing quality, Save/reopen, physical memory or mobile coverage.

Two tests reproduced missing classification before implementation. Final 16 focused tests cover JSON/stream rejection, queue reuse without disposal, untyped look-alike text, unrelated inference errors and cancellation identity. Build, 116 test files / 4,156 tests, root lint and diff checks passed. Existing converter PromiseRejectionHandledWarnings persist. Read-only review found no Important/Critical issue.

The matcher intentionally targets the error format observed from the pinned SDK; other native formats remain generic until verified. Reproduce the corrected UI run after building with node docs/evaluations/probe-cpu-long-writing.mjs on the historical 5193 server and its isolated CPU profile. Headers are injected and Service Workers blocked; the probe must not run concurrently with another user of that profile. It creates and edits only synthetic test documents.

# Isolated first-editor startup and actual CPU offline inference

This evaluation changes no product source, hosting configuration or IM UI. It tests the `aae9cf0` registration/cache-response fix before enabling global acceleration headers.

## Fresh native-editor startup

`probe-isolation-cold-start.mjs` uses an ephemeral HTTP proxy over the port-5193 preview. COOP `same-origin` and COEP `require-corp` are present from the first response. Each of DOCX, XLSX and PPTX gets its own new Chromium context with no preexisting browser storage; there are no Playwright resource routes. The actual application installs and gains control from `/sw.js?isolation=1`.

All three complete document/full API loading with main document and iframe isolated. Native PasteText writes a marker (Excel B2); the native Save toolbar downloads the document. Actual homepage file-chooser reopening preserves each text snapshot exactly. Afterwards the same type starts offline, both frames stay isolated, navigator is offline and an uncached request fails. Before each offline navigation, the proxy refuses connections, closes existing connections and refuses in-flight upstream replies. Each offline row asserts zero upstream responses across navigation and startup, including the brief emulation reset. Native spellchecker JS/WASM are served with 200 on each context's first boot, then 304 on warm startup. The report's final pass requires three completed cold/save/reopen rows, three offline rows and no page errors.

Artifacts: `probe-isolation-cold-start.mjs`, `2026-10-03-isolation-cold-start.json`.

## CPU inference with a real controlling worker

`run-cpu-isolated-sw.py` temporarily instruments the generated native Wllama `createChatCompletion` entry to record the actual loaded model's `getNumThreads()` and `isMultithread()` values. It also retains the prior writing-response diagnostic hook, which this chat probe does not use. The runner checks unique injection locations, restores the exact generated bundle bytes in `finally`, and prints their SHA-256 values.

The CPU probe reuses the isolated test profile's cached Qwen3-0.6B GGUF. It hides WebGPU to select CPU. It unregisters only existing worker registrations and removes only cached agent-plugin/esm assets so the diagnostic code executes; model caches and OPFS data are retained. The production app registers and controls the isolated editor through `/sw.js?isolation=1`.

Final actual results:

| Phase | Actual threads | Multithread | Main/iframe isolated | Reply | Uncached request |
| --- | --- | --- | --- | --- | --- |
| Online | 4 | true | true/true | HELLO. | succeeds |
| Offline | 4 | true | true/true | OFFLINE. | rejected |

Both phases have zero visible/page errors, zero previews, and unchanged native document text. One observation per phase: UI response time 3,596 ms and 3,146 ms respectively. These short prompts are a compatibility check, not a performance benchmark or writing-quality pass.

The online host policy is injected through Playwright same-origin routing. **That route is removed before going offline.** The offline editor and Worker must then load through actual caches/native cached responses; A replacement route aborts every network request before emulation is switched, including the brief reset. No route can fulfill a missing network resource. Only replies added after this request begins are accepted. Navigator reports offline and the random uncached fetch fails. Inference reloads the model in a new editor navigation, rather than merely continuing an already initialized chat.

Generated bytes restored and checked:

- `agent-plugin-B0oBnNUo.js`: `2b5eeb7c42844876304a86a4a0648e13a2d6843efdc8851c8024a44eabda0d67`
- `esm-DlYNP7Qx.js`: `0e195b0b3450067e12a30569a03f584fc41a7d7ef57cf66f4dc92a82e9315d61`

Diagnostic bodies may remain in this isolated browser profile's app asset cache; they are not shipped bundles. A subsequent instrumented run explicitly clears those asset entries. The profile's model cache remains intact.

Artifacts: `probe-cpu-isolated-sw.mjs`, `run-cpu-isolated-sw.py`, `2026-10-03-cpu-isolated-sw.json`.

## Retained failed controls

1. Initial CPU harness selected `.cui-msg-assistant`, while actual messages use `.cui-msg-agent`. Native runtime already proved four threads, but replies were empty in the harness and the run failed. Initial source and JSON are retained.
2. With the correct selector, both replies succeeded, but the header-injection route was still active offline. Navigator was offline while an uncached fetch succeeded; the run correctly failed its offline gate. That source and report are retained separately. Removing the fulfillment route before offline is the first correction. Independent review identified the emulation-reset gap and historical-reply matching risk; the final probe blocks all requests during the entire offline phase and checks only newly appended replies. Earlier reset-control source and JSON are retained with their narrower scope. The native cold probe also refuses server connections and asserts zero upstream responses throughout offline startup.

Root lint and the final probe-specific oxlint pass. No product source changed, so the preceding build/full-suite result is not represented as a new test run here.

## Remaining scope

This proves Chromium cold native startup and cached CPU inference under the tested policies. It does not prove cold model downloads, writing quality, all GPU models under this controlling worker/policy combination, redirected Worker modules, document styling fidelity, physical Safari/iOS/Android/Firefox, or deployed header behavior. Global acceleration headers remain disabled; the broader local-AI goal stays active.

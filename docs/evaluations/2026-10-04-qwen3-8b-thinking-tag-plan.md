# Thinking plus tagged final JSON: feasibility only

Installed SDK source applies JSON grammar masking from the start of constrained decoding. enable_thinking=false also seeds an empty completed thinking header. Therefore merely enabling thinking while retaining full-output JSON does not by itself establish a reasoning-compatible format. Current SDK public ResponseFormat supports structural_tag, allowing unconstrained text outside triggered tag spans and JSON schema within a final tag.

Prototype actual Qwen3-8B on the same four known document-writing cases: current versus enabled thinking, temperature 0.6/top_p0.95/max1536 and triggered <final> JSON schema. Candidate system/format instructions explicitly request tagged final JSON after thinking. [Original publisher instructions](https://huggingface.co/Qwen/Qwen3-8B) guide thinking sampling; this is SDK/browser compatibility testing, not publisher quality proof. It changes multiple factors, so do not interpret it as a causal ablation.

Keep source/instruction JSON payload identical; capture exact Worker requests/model identity and raw outputs. Require complete tagged final JSON to assess candidate body; absent tags/length truncation are failures. Existing production writing parser remains unchanged and must refuse tagged reasoning output without altering source. No reasoning text is surfaced in the chat UI, no preview or new user workflow. Report only final-body semantics and mechanics, not reasoning prose. Current variant may apply/Undo/Redo as usual. No Save. Known examples, one sample each fixed order, not heldout/repeated quality acceptance. A successful prototype would still need a safe adapter and full existing guards/lifecycle/native regression coverage before any production adoption. Do not strip arbitrary content or treat malformed/tagged output as verified writing.

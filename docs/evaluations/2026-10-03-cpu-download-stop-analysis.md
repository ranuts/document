# CPU model download Stop

Actual Chromium production IM default-local CPU fallback entered the SDK GGUF download path. The probe deliberately denies OPFS access and makes Cache API model reads miss, without deleting the existing OPFS model. A real model GET was intercepted before its response. SDK supplied exactly one AbortSignal; visible loading Stop triggered exactly one abort. Stopped UI hid Stop and enabled Load. Aborting/releasing the held route did not change Stopped or add a visible error. Restoring cache access and using existing Load retried into actual CPU Qwen3 0.6B, which generated Hello with no page or visible error. The profile is isolated ai-offline/profile; preview is 5193.

This is cancellation while awaiting a download response, not partial stream-byte reception, metadata-fetch cancellation, GPU model shard downloads, physical network disconnection, cache eviction or true OOM. Report retains raw initial counters and actual held request, not just passed=true. Source hash identifies the accompanying reusable probe. Existing model cache is reused for retry; this does not prove re-downloading the entire model after cancellation.

Following WebKit attempts observed SDK model GET with AbortSignal but could not hold the route, even with broader matching including redirected CDN. Those are unresolved harness routing diagnostics, not evidence that WebKit Stop fails. Chromium reliably held the actual request and is the sole passing scope here. All diagnostics remain failed.

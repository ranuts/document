# Current CPU formal rewrite: raw response and compact prompt control

Current production CPU Qwen3-0.6B returned valid completed JSON, but changed `2026-10-08` into `October 8, 2026`. The existing numeric/date guard rejected the result before application, preserving the exact selected document text. Baseline raw output was `Alex is to pay 1,250 EUR on October 8, 2026.` This reproduces the date-fidelity problem with the current build; it is not a JSON parse error, a timeout, or an unchanged model response.

A single-variable experimental control replaced only the writing request prompt with a shorter rewrite-specific instruction; engine, schema, validation, source and requested style remained unchanged. Input tokens fell from 447 to 232, prompt processing from 29.04 s to 14.37 s, and observed UI completion from 33.90 s to 18.20 s. However the raw output was `Hey, Alex will pay 1,250 EUR on October 8, 2026, okay?`: the date still changed, and the formal-style instruction was not fulfilled. The result was correctly rejected. The compact prompt is not adopted. These are one-off observations with stochastic defaults, not a controlled performance benchmark or model reliability estimate.

## Diagnostic fidelity

Initial response-capture attempts did not execute: isolated persistent-profile script requests bypassed route interception, and the first generated-bundle capture also produced no marker. Those runs establish visible guard rejection only and do not establish raw output. The probe was corrected to require a nonempty raw response capture. It unregisters service workers and removes only cached agent-plugin application scripts in the isolated test profile before navigating away and loading the instrumented build. Baseline reset observed one registration and nine matching script entries; model caches were retained. The next run captured the actual validation-boundary response successfully. This supports cached script reuse as the diagnostic obstacle; it is not evidence of a production offline-cache defect, because diagnostic edits deliberately keep the same generated asset URL.

The Python runner temporarily instruments the generated bundle and restores its original bytes in finally. Archived probe sources, hashes, runner hash and original bundle hash are recorded in both reports. The compact runner was actually executed; the baseline was captured with the archived baseline probe and equivalent raw-capture-only generated-bundle instrumentation. Source syntax and oxlint checks pass, and the restored bundle hash matches the original. No production source changed in this investigation.

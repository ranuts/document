# Registration settlement is sufficient in the tiny reproduction

Independent tiny loopback WebKit 26.5 probe; relative to df7a03f, the first register call is now awaited before navigation. In the immediate case its promise returns while the worker is still installing, demonstrating that full controller/cache readiness is not the pre-navigation condition. The destination registers the same worker again; that promise resolves, all bootstrap/install/activate markers arrive, the worker activates, the tiny cache exists and the destination is controlled. The separate full-control case also succeeds. All contexts/server/browser cleanup completes.

This identifies registration settlement as a smaller sufficient lifecycle condition in this reproduction, not a required whole-cache wait. It remains a single synthetic case per path, not a product fix or universal browser guarantee. Actual Home opens its picker synchronously and stashes the selected file asynchronously before navigating; a bounded registration handoff can be evaluated after stash without moving the picker outside user activation. It must not wait indefinitely, equate registration with offline readiness, or prevent file opening if registration fails/does not settle. Product behavior still requires direct native validation and meaningful failure/timeout tests before any implementation is accepted. No product code/build/suite change or global offline/semantic acceptance is claimed here.

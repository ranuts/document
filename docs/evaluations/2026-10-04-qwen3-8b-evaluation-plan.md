# Qwen3-8B dedicated-writing candidate plan

Current installed SDK catalog supports Qwen3-8B-q4f16_1-MLC with context_window_size 4096 and vram_required_MB 5695.78. This is an SDK estimate, not actual memory allocation, download size, device compatibility or quality proof. Original [publisher model card](https://huggingface.co/Qwen/Qwen3-8B) describes multilingual/non-thinking support; this browser test uses the catalog's MLC quantization and current app schema/non-thinking controls. No production default change.

Predeclare the same four known source/task/instruction cases as document-writing-route-cases.json and compare captured requests with the existing default-model native run. One sample per case, current structured schema, temperature 0, 512-token output cap, existing numeric/currency/length guards. Require exact status title and Worker model ID; CPU fallback is a load failure for this candidate, not success. Check raw output, actual native application/refusal, no previews, unchanged bundle and exact Undo/Redo on edits. No Save. Manually assess future payer/recipient, negation, proposal status, inspection-pass prerequisite, pending/unauthorized states, allegation attribution and formal/language quality. Loading and edit counts are not semantic scores. Four-case screen does not establish seven-language or repeated acceptance.

Large-model initial download may take time; observe the same live process instead of restarting on an observation timeout. Candidate evidence must be terminal before a completed/failed decision. The heartbeat logs current UI loading status every 30 seconds. High-resource availability alone will not justify adopting the model.

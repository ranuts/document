# Excel formula lifecycle cleanup without blocking cached return

The prior real Excel probe failed cached admission with `UnloadHandlerExistsInSubFrame`; a delegated registration observer located the cell SDK's additional window unload handler. This is separate from main app property cleanup covered by guard 17. The callback only notifies external formula editor closure when a departure warning was requested and formula editing remains active.

The audited vendor registration in `public/sdkjs/cell/sdk-all.js` now uses pagehide. Its beforeunload warning still checks the current external formula editing mode, prevents departure and sets returnValue as before. Beforeunload recomputes the flag each time; pagehide snapshots and resets it before conditional cleanup. This matters because BFCache retains the closure: the initial event-only migration left the flag sticky and could close a later formula editor after a return or a cancelled warning. Source review caught this; two additional tests reproduced the stale flag before the corrected repair.

Tests execute the actual shipped registration closure rather than a hand-copied callback. Initial migration test first failed because native unload still closed the editor, then passed after migration. Final five tests cover unchanged active warning, cleanup on persisted pagehide, no warning/no cleanup, inactive editor and cancelled departure, repeated cached return without new warning, next departure after cancelled warning, and single flag consumption. Final full regression: 132 files / 4,436 tests passed. Existing asynchronous rejection warnings remain. TypeScript, changed-test lint and whitespace checks passed. Final production build passed with the existing advisory large-chunk warning. Source review finds no remaining important issue.

The patch is deliberately restricted to this audited SDK callback, without a general window event interception or deletion of external editor cleanup. SDK upgrades must re-audit the tested registration boundary. No preview, model prompt, cloud fallback or extra confirmation behavior was introduced. Unit pagehide events and external editor conditions are synthetic; they do not independently certify real multi-window external-editor synchronization or physical-device behavior. Native browser regression evidence will be recorded separately.

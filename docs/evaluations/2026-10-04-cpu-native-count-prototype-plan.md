# Native CPU count prototype acceptance plan

Use only the isolated SDK 3.6.1 checkout and pinned llama.cpp revision documented in the build feasibility record. First compile the unmodified CPU compatibility baseline; do not change files while that build reads them. Preserve a terminal failure if the local Emscripten mismatch prevents compilation.

The experimental action will accept the exact chat completion options, apply `oaicompat_chat_params_parse` with the loaded `meta->chat_params`, and tokenize its `prompt` through `tokenize_input_prompts` with both special-token flags true. Return prompt token count and `meta->slot_n_ctx`, not configured global capacity. Require exactly one text-only prompt and no files/media; reject unsupported requests rather than produce incomplete counts. Do not enqueue completion, create a response reader, evaluate the model, or modify KV state. Expose it through a new explicit glue request/response and native dispatcher action, with matching generated TypeScript serialization.

Before production adoption, capture actual requests and compare counts against generation's prompt usage on short ASCII, Chinese, mixed script, multi-turn messages, custom system instructions and tool-bearing messages. Include the previously overflowing 1900-character Chinese custom system case. Count must include schema/template effects where present; unsupported capabilities must fail explicitly. Repeated preflights must produce stable counts and leave a subsequent deterministic generation identical to the baseline. A failing preflight must leave the loaded model usable. Reserve output tokens separately and test the exact context boundary.

Build success or static source inspection alone does not satisfy these runtime gates. The prototype must remain outside the product until counts, no-generation behavior, cancellation/lifecycle handling, memory cost and actual browser compatibility are verified. Baseline compiler differs from the distributed SDK's pinned toolchain; resolve or document that limit before claiming artifact equivalence. IM receives no additional controls or preview cards.

# Bounded Home registration handoff

The product now retains Home's existing registration promise and, after local file stashing, waits for it to settle before navigating. The wait is at most 1,000 ms; rejection, missing service workers, an absent pending call, and timeout permit opening. This does not wait for activation or cache completion. File-picker activation stays synchronous. No UI or confirmation was added.

The first test run against unchanged production code had four behavior failures: successful stash, rejected registration, stalled registration, and failed-stash fallback all departed Home before registration settlement. After the fix the focused scripts/handoff run passed 39 tests. The full suite passed 135 files / 4,467 tests. TypeScript, changed-file oxlint, diff checks, and production build passed. Existing two PromiseRejectionHandledWarnings and the build's large-chunk advisory remain. Independent review found no issues.

The native driver forwards the unchanged production build through an owned loopback origin. It does not replace scripts, wrap registration, seed caches, or delay the picker until controller readiness. In two fresh Playwright WebKit 26.5 sessions, immediate Home selection imported the actual saved DOCX, and native GetText returned exactly `WEBKIT_WORD_20261005\r\n`. The real worker was activated and controlling the editor, with both core/runtime caches. After closing the first page and stopping the entire origin server, a new Home response came from the service worker and selecting the same file again restored identical native text. Both contexts/browsers and the server were closed; no page errors occurred. The driver exits nonzero if any run fails, and the JSON was independently asserted.

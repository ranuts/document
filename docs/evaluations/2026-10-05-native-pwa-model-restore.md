# Restore local model choice and URL after installed PWA restart

The panel now remembers the selected browser-local provider and HTTP(S)-resolved GGUF URL in this origin's localStorage. Provider restoration only accepts the existing `wllama` option; every other stored value falls back to automatic local mode. URL restoration uses the existing shared model-artifact policy. Invalid/empty URLs are not restored. Changing the URL stores the valid resolved address; choosing local GGUF files clears the remembered URL, because file handles/blobs are not restored. No cloud provider, credential field or extra UI was added.

Opening the assistant restores and loads an available URL model, using the existing background editor-ready/idle gate when the panel is mounted in the background. CPU mode without a valid remembered URL still waits for manual model/file selection. Stop, cleanup, retry and concurrent-load guards remain the existing implementation. Tests cover actual preference restoration/loading, preference edits/file clearing, provider whitelist and invalid saved CPU URLs. Existing panel fixtures now clear these persistent preferences between independent cases.

A fresh headed Chromium 151 native installed-PWA probe seeded a self-hosted Qwen2.5-0.5B Q4_K_M model and PPT editor, then closed the browser and the complete owned application/model serving origin. Independent fetch failed. On browser process restart, the installed standalone PPT window automatically restored `wllama` and the exact same model URL, and loaded the cached CPU model. The offline phase did not select the provider, fill the model address, dispatch a settings change or click Load. It only opened the sidebar and waited for model readiness.

Actual inference produced a brief greeting (`Good day!`; raw message row includes its existing write-action label). IM then added a slide and wrote `PWA_PPT_四季_2026` in a new text box. Native two-step Undo/Redo matched the original/modified slide snapshots. Save's download fallback produced a 36,482-byte PPTX with SHA-256 `1a4d001c2565e6fe7a6daf1b7e90ca849615f023080d429e59bc33c96fc2a72d`; opening that file initialized the actual PPT engine and restored exactly the two-slide text structure. No IM errors or previews were observed. The test installation and final browser context were removed/closed; the owned server stayed down.

This closes the manual custom-URL re-entry gap for URL-based local CPU models on this browser/origin. Local file restoration, expired/signed URL refresh, all-origin network privacy, physical network isolation, OS reboot/shortcut launch, mobile/GPU/hosting/cache eviction and semantic writing quality are not accepted by this test. File System Access is deliberately unavailable to exercise the existing Save download fallback; its native system picker remains unverified. A greeting is availability evidence, and bounded direct/tool grammar operations are not arbitrary model tool planning.

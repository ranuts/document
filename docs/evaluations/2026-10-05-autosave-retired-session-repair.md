# Retired document recovery exports

An asynchronous snapshot retained its captured session while global session changed. Controlled tests reproduced two defects: late export success still wrote the old history row after session stop/replacement; a late third export failure called stopAutosaveSession and stopped the replacement document. Autosave now checks session identity/stopped state before reading export bytes, after byte conversion, after storage and in the failure handler. Finally clears only the captured exporting flag.

Review identified additional asynchronous storage boundaries: quota estimate, payload conversion, database opening and quota eviction/retry. Each session now owns an AbortController, aborted on stop/replacement. putSnapshot accepts an optional owner signal, checks cancellation across asynchronous preparation and binds cancellation to native readwrite transactions for both snapshot writing and quota eviction. Completion/abort removes the signal listener. In-progress cancelled transactions roll back atomically; committed transactions remain committed. Callers without an owner signal preserve previous storage behavior. Cancellation is not a storage failure notification for a retired autosave session.

Initial late-export and late-failure tests failed as expected before the identity guards. Four further boundary tests failed before cancellation wiring. Seven added tests cover late success, late failure, retirement during quota estimate, in-progress write rollback, cancellation at quota failure, retirement during autosave storage estimate, and rollback of quota eviction while old blobs are being deleted. Tests read actual fake-IndexedDB stored rows/bytes rather than assert only mocked storage calls; controlled export delays and native method spies provide the interruption boundaries. Full suite passes 132 files / 4,449 tests, retaining the existing two asynchronous rejection warnings. TypeScript, changed-file lint, whitespace checks and production build pass. Build's advisory large-chunk warning remains. Final source review found no remaining important issue.

Native Chromium 151.0.7922.34 verifies two controlled cases using actual product SDK export and native IndexedDB in fresh owned contexts, service workers blocked. The exact rebuilt shared chunk exposes the public recovery preference API at alias f; its source and SHA-256 are recorded, and the chunk was inspected against the shipped setAutosaveEnabled implementation. A synthetic hidden visibility transition requests recovery (no cached departure). In estimate mode, storage estimate is held, the real preference API disables/stops recovery, then the estimate resolves. No doc/blob row is present. In write mode, an observer calls the same API immediately after native blobs.put queues a request; the native transaction emits abort and leaves no doc/blob row. Both retain B2=7, and a subsequent actual IM sum into B11 yields 7 with no page/chat errors. Contexts and browser close. This is deliberate fault injection/API control, not a natural quota exhaustion or full preference UI test.

# 本地 IM 质量改进设计

## 基线与目标

[真实模型验证](2026-09-27-indexeddb-validation.md)的 24 次编辑提案中，21 次结构合法，但出现占位文字、错误单元格、未拒绝删除和多单元格请求；9 次写作中 4 次出现 JSON 包装。结构合法率不能作为任务成功率。

本轮首先交付受约束的生成协议和宿主目标绑定，禁止模型自行决定单元格。保留现有预览、确认、过期和取消机制；默认模型暂不变更。随后实施明确的写作任务入口、执行后的实际内容校验以及 4B 对照测评。这些阶段必须分别记录证据，不能把规划写成已验证的能力。

## 协议

WebLLM 提供独立的 JSON Schema 生成接口，使用任务专属系统提示、temperature=0 和不含工具的请求。模型只返回 status（ready/unsupported/needs_clarification）和 content。应用负责构造工具及地址；不提供含 B2 或 requested value 的示例。其他后端使用同一协议并进行严格解析，但不能宣称拥有约束解码。

电子表格要求选中唯一单元格；宿主计算 A1 地址，并在生成和执行两处绑定地址。范围选择拒绝生成，生成过程中移动光标继续使提案过期。公式、空值、多单元格写入仍不支持。JSON Schema 只能保证结构，不能证明事实或意图正确。

## 分阶段验收

1. 协议与目标绑定：测试生成参数、unsupported/clarification、额外字段、截断、错误地址、多选区域；既有测试和类型检查通过。
2. 任务分流：聊天、改写、翻译、摘要、编辑有明确入口；不依赖小模型自由选择工作流。未选中文本时不擅自改写全文。
3. 执行校验：读回编辑器真实内容，区分已发送、已验证和失败；失败不得自动重复执行。分别验证 DOCX/XLSX 的 Undo。
4. 模型比较：同设备同协议比较 1.7B/4B，记录语言、事实保留、拒绝率、时延、峰值资源与失败原因，再决定默认模型。

## 限制与记录

不把降低温度当作准确率保证，不静默修补任意 JSON 写作输出，不启用 Qwen 原生工具调用，不修改用户已有 CSV 文件变更。每阶段完成后补充实际结果；尚未执行的阶段保持未完成状态。

## 第一阶段实施记录

已接入 WebLLM 独立 JSON Schema 请求，移除工具/地址示例；宿主计算单个选区的地址，并在 `ReviewedAction` 中再次核对。显式赋值由应用处理：英文 `write plain value 1250 to C3` 或中文 `将所选单元格的值设为："Alex未批准第二阶段"`。非数字文本必须为 JSON 双引号字符串；不把“今天的日期”等计算指令当作值。其他自然语言提案仍依赖模型，不能保证正确。

[真实模型探测原始记录](2026-09-27-im-quality-model-probe.json)：约束生成的三例全部结构合法，但中文值和多目标拒绝失败，只有英文数字赋值正确。修正后在 Chrome 执行六例协议验证：三个字面值正确绑定 C3（含值为 B2 的文本），地址冲突、附加操作和计算请求三个例子均在推理前拒绝。后六例验证的是应用协议，不是模型能力，也未执行编辑器写入。

独立审查指出“赋值后缀可能吞掉其他操作”和“地址样式文本误判为目标”，已通过限定字面值语法及分别解析目标修正，并添加回归测试。写作路由、执行读回和 4B 对照仍属于后续阶段，尚未实施；不据此修改默认模型或宣称整体质量达标。

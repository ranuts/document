# Actual registration calls span Home departure

Fresh WebKit 26.5, unchanged f2eb0ed, owned forwarding origin. Diagnostic init script in top pages wraps the actual navigator.serviceWorker.register, delegates immediately with original receiver/arguments and returns the original promise. Separate handlers send start/resolve/reject observations to an owned Playwright binding; pagehide is also observed. No waiting, registration restart, cache mutation or Open delay is introduced. Observation callbacks can affect scheduling, and bindings from departing realms may lose messages; absence is not a proof a promise never settles internally.

Recorded sequence: Home starts `/sw.js?isolation=1`; 87 ms later Home emits pagehide; 34 ms afterward `/editor?open=local` starts registration using the absolute URL of the same worker. No resolve/reject observation reaches the binding. Native DOCX opens with exact text, but the later actual registration snapshot is still installing, controller null and caches empty. Page errors are empty; cleanup completes.

This connects the Home navigation sensitivity to concrete product registration calls and establishes that the editor does attempt to register after departure. It rejects the simple hypothesis that the destination omits registration entirely. It does not yet establish duplicate-register queue internals, a safe cancellation/recovery, or actual Safari behavior. Source wrapper evidence must not be promoted into a blocking UI requirement. Next minimal probe should model the second same-scope registration after a navigation while the first remains unsettled, and compare with settled registration. No product code/build/test change, server-closed reopen, full offline or semantic-quality acceptance is claimed.

# Restoring panel resources after a cached page return

Source inspection after `8558eac` found that resize handles, editor sidebar entry, scope timer and native review callback were detached on pagehide but were not remounted on persisted pageshow. Several cleanups were registered only once, so repeated return cycles could also leave newly restored resources attached during the next hide. The viewport helper already had a remount path; the panel now restores the other interactive resources in that path and cleans up their current instances on every hide. Detached panels do not remount or publish a sidebar entry.

Returning refreshes provider hints and runtime readiness. The prior local model is still released on hide; the UI no longer preserves a stale loaded/preparing note after restore. Existing cleanup-failure guidance and asynchronous cache-result guards remain. No automatic inference retry or document operation is triggered. The original conversation remains in its existing store; model/history durability is outside these UI regressions.

Two new integration regressions first failed: repeated cached-return events with resizing/sidebar reopening, and stale loaded guidance after return. After the repair, 130 files / 4,426 full-suite tests passed, TypeScript and changed-file oxlint passed, whitespace checks passed, and the final production build passed. Source review identified the stale guidance issue, then found no remaining important issue after correction. Existing asynchronous rejection warnings remain in the full suite.

Tests dispatch synthetic PageTransitionEvent events and use a mock local provider. They establish component lifecycle behavior, not natural browser back-forward-cache admission, restored model inference, physical device or offline acceptance. Native-browser navigation and exact history/worker behavior still need separate observations. The loaded-note test deliberately seeds stale text; it is not an actual loaded model measurement.

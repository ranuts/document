# Saved Word font failure: delayed first request

Authoritative source inspection and retained a261718 request ledger narrow the resource problem. `/fonts/100` appears exactly once, during Save; it was never requested during the observed online page/model warm-up or restored editor boot. The local deployed source `public/fonts/100` exists (6,868 bytes; SHA-256 recorded in the JSON diagnostic). This rules out an absent source file as the immediate explanation for its failure when the forwarding origin was unavailable.

The production service worker's vendor cache-first branch includes extensionless `/fonts/` resources, so this request is distinct from the explicit bypass for ttf/woff/otf/eot files. Install precaching includes converter assets and the font catalog, but does not enumerate the font binaries. Consequently, warming the page/model does not guarantee a font first requested at Save is cached. The converter source also intentionally tolerates missing font faces as substitution rather than failing conversion; this is consistent with the intact DOCX artifact, but does not locate this particular page TypeError's caller.

The initial catalog lookup mistakenly searched for style index 100 rather than resolving file name `100` through `__fonts_files`. Correct lookup, following docs/fonts.md, places the file at position 103; the `ASCW3` row points to position 103. The JSON diagnostic now records this actual mapping. A numeric filename is not necessarily its array index.

Source inspection of the shipped Word SDK shows special handling for ASCW3: the catalog row is removed from ordinary family construction, its file Id retained, and embedded font bytes are registered via `AscFonts.CreateFontData2`; a synthetic font-file entry with that Id and Status 0 is appended, then a new ASCW3 info row points to the appended entry. The SDK also uses ASCW3 for supported checked/unchecked control symbols. This establishes its special built-in-symbol role, but no runtime caller stack ties the failed Save fetch to a particular branch yet. Export font enumeration can see that synthetic entry; using its already embedded stream instead of re-fetching is a candidate requiring cross-realm/worker verification, not an implemented fix.

The later controlled prefetch result a4f7c42 records the cached response and removes the observed Save font/page errors while preserving native write/Undo/Redo and artifact integrity. This supports the cache-miss diagnosis. A product fix must account for the special embedded-font path or justified warm-up resources; blindly precaching the entire font tree would have unmeasured download/storage cost. These diagnoses add evidence without changing product/cache/model/budget policy, and do not close offline completeness or layout verification.

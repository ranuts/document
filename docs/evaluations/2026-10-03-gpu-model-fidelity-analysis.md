# Qwen3 1.7B versus 4B: native writing fidelity

Decision: retain the existing default. This experiment does not demonstrate that selecting the larger cached model fixes practical writing quality.

Six identical Word selected-text tasks ran once per model on desktop Chromium/Metal. Three are previously inspected sampling fixtures (regressions), three new fixtures cover inventory/action separation, conditional approval and attribution/uncertainty. The new fixtures have now been inspected and must not subsequently be described as independent acceptance cases. Model order was 4B first, 1.7B second, without counterbalancing; these are exploratory observations, not model-wide quality rates or performance benchmarks.

Actual Worker requests were captured and compared: identical messages, schema, temperature 0, top-p and token budget. The configured model identifier was verified in each Worker request. Production prompts, schema and guards stay intact; route-local diagnostics do not change on-disk bundles. Isolation headers are injected and service workers blocked. No product/default changes, physical mobile, memory, Save/reopen or offline reliability claims.

| Fixture                        | Default 1.7B                                                             | Candidate 4B                                                                                                                           |
| ------------------------------ | ------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------- |
| Formal English, supplies value | Applied an incorrect money-delivery substitution.                        | Retains supplies/value, but keeps conversational “correct?”.                                                                           |
| Formal Chinese, supplies value | Applied faithful but awkward wording.                                    | Raw wording preserves value; localized date format is rejected by the existing literal guard.                                          |
| Proposal summary               | Applied a faithful shorter summary.                                      | Raw output retains facts but is not shorter, so rejected.                                                                              |
| Inventory/action separation    | Date malformed as 2033-0321, rejected.                                   | Applied separate inventory actions and quantities but retains “okay?”.                                                                 |
| Conditional approval Chinese   | Applied a shorter summary retaining pending approval and uncertain date. | Raw output localizes date and is rejected; it implies approval is still needed rather than explicitly stating it has not been granted. |
| Attribution and uncertainty    | Changes 2033-03-21 to 20 March 2033, rejected.                           | Applied claim attribution, possibility and lack of agreement, but retains “okay?”.                                                     |

The 4B run applied 3/6 actions, the 1.7B run 4/6. These are mechanical acceptance counts, not quality pass rates. All applied edits had exact native Undo/Redo; all rejected results retained the exact original selected text. Both runs had zero previews, zero page errors, zero external requests and unchanged bundle bytes. Default 1.7B's money-delivery substitution remains a false acceptance the literal guards cannot detect. Conversely, correct localization of a date can be rejected because production intentionally requires exact date literals; this experiment did not weaken that constraint.

The comparison provides useful evidence about the next intervention: model size alone leaves instruction following problems, especially removing conversational endings. Subsequent experiments should compare writing-specific message organization and explicitly preserve semantic roles, using these as regression cases plus fresh acceptance fixtures. Neither model is established as generally reliable for autonomous writing by these results.

Reproduce with `probe-gpu-writing-sampling.mjs`, `WRITING_EXAMPLES_VARIANTS=current`, `WRITING_EXAMPLES_REPETITIONS=1`, `WRITING_EXAMPLES_CASES=docs/evaluations/2026-10-03-gpu-model-fidelity-cases.json`, a unique `WRITING_EXAMPLES_REPORT` path, and `WRITING_GPU_MODEL` set to the appropriate exact model ID. Existing cached profile and preview port 5193 are required. Do not run both models concurrently in the same profile.

`python3 docs/evaluations/verify-gpu-model-fidelity.py` checks both archived reports, actual model selection, equality of all request fields, byte hashes, expected rejection preservation and native history. It deliberately makes no semantic quality assertion. Probe syntax and repository lint are also checked; no build/full product test rerun is needed for this evaluation-only change.

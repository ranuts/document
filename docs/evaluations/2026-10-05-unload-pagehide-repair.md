# Product unload cleanup migration

The three shipped desktop main editors (Word, Excel, PPT) have the same `onUnload` cleanup body: cancel `continueSavingTimer`. The new guard preserves the current handler and late vendor assignments, clears the native unload listener, and invokes the same handler with the iframe window binding from pagehide, including cached departures. It does not remove the app's unsaved-document warning or replace Save. Null assignments disable the stored handler. Repeated installation is idempotent; unsupported/nonconfigurable properties keep the native fallback, and failed installation restores the original descriptor/handler.

The guard is mounted through existing same-origin iframe preparation. Tests first failed for migration and timer cancellation, then passed: original/late/null handlers, exact window binding, no native unload callback, single pagehide invocation, actual fake-timer cancellation, and all three shipped main-app cleanup contracts. The full regression initially caught the missing project guard number; the source comment now identifies guard 17 and the current full suite passes 131 files / 4,431 tests. TypeScript, changed-file lint and whitespace checks passed. Production build passed before the final comment-only numbering correction; no runtime statements changed afterward. Existing asynchronously handled rejection warnings remain in the full suite. Source review found no important issue.

The prior isolated migration achieved two native cached returns, but it was an intervention and is not acceptance evidence for this checked-in guard. Real production-guard navigation, native Save/Undo/Redo and loaded-model return remain to be verified. The source contract tests audit the desktop main bundles; they do not validate unused vendor mobile editor bundles or all future vendor versions. Physical mobile, offline/PWA and OS reboot acceptance remain open. No preview or extra confirmation flow was added.

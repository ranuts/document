# CPU abort-message failure investigation

The earlier real SW-blocked offline model reload reported `t.replace is not a function` together with a WASM network failure. To collect an error stack, the same browser flow was repeated after subsequent PWA cache tests. It now succeeds, with no page errors and a Hello reply. A second diagnostic attempts to abort matching WASM requests through a route, but also succeeds. No route-hit or denied-resource event is recorded, so it cannot be treated as effective failure injection. Both successful reports and their drivers are preserved; neither proves the earlier runtime issue was fixed.

Installed @wllama/wllama 3.6.1 source identifies a vulnerable signal.abort handler in src/worker.ts: it destructures message as a string and calls message.replace directly. The generated ESM and CJS entries contain the same code. A synthetic probe extracts and executes that actual installed ProxyToWorker class, passes a signal.abort payload whose message is an object with a string message property, and observes an unhandled TypeError containing replace is not a function in both entries. No error return is substituted. This reproduces the handler defect for that input shape, not the exact uncaptured payload of the earlier browser failure.

The next product change should normalize abort-message and stack types before using string operations, then ensure pending initialization/generation requests reject instead of hanging. The repository already owns a pnpm patch for this SDK and proxy failure regression tests, so the repair can extend that existing integration rather than add another runtime dependency. Cleanup, standard string aborts, non-string messages and both module entries require validation.

The verifier binds executed probe bytes, checks both synthetic TypeErrors and the later browser successes. SDK hashes are checked against the currently installed patched dependency; those bytes are mutable and a later patch will invalidate that part of the historical check. This evidence does not certify a real network failure payload, UI recovery, offline cache failure, privacy, physical devices or a completed fix. No product code changed in this investigation.

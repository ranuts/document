# Rendition prompt alone does not establish writing fidelity

Four completed requests, process exit 0 and closed context. Mechanical comparison proves each request is the prior two-stage final request with only the model-extracted ledger line removed; the frozen rendition prompt, authoritative original task/source, model overrides and decoding settings remain unchanged. No extraction request was issued.

Bounded manual review: two narrow passes, two failures. Chinese delivery-team actor retention and Spanish-to-Portuguese heading/fact preservation improve with the extra prompt alone. The intermediate extraction is therefore unnecessary for those observed local improvements; this does not prove all ledger variants are useless. Japanese still reformats ISO date. Portuguese omits archive-team actor, changes permission to future execution, and replaces a currently unvalidated backup with a backup not yet made. Proposal nonapproval is restored in Portuguese, but this does not offset the remaining semantic changes.

The prompt mentions an additional fact ledger although none is supplied; retaining it keeps the final-request contrast exact. This is a known-source, fixed-order, one-sample comparison to prior completed runs, not a representative language benchmark. No product prompt/model is adopted. No native application, untouched transfer, physical-device/offline certification or exact cached-library consumption proof. Next work must address literal preservation and factual relations, not add intermediate extraction merely because selected outputs improved.

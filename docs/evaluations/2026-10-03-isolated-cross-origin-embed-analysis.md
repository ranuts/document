# Cross-origin embedded editor with old cached responses

This is a local candidate-hosting compatibility diagnostic, not a production failure report. Global COOP/COEP headers remain disabled in product hosting configuration.

The probe uses an ephemeral HTTP proxy for the app and a second-origin parent on a different local port. Both origins have the same schemeful site (127.0.0.1), so this specifically tests cross-origin ancestry while keeping the warmed app storage reachable; it is not proof about every third-party storage partition.

The exact old worker from `2a675a7` warms Word under nonisolated hosting, with the current vendor hash. The recorded cached native iframe response lacks COEP. A nonisolated parent then embeds the editor and sends the supported `document:open-buffer` protocol with a local generated DOCX fixture. The control waits for actual native document/full API readiness and succeeds.

With the same parent, document and protocol, the proxy adds COOP `same-origin` / COEP `require-corp` to current network responses. The parent and embedded app remain nonisolated. The app therefore still registers `/sw.js`, without the isolation query flag. The native editor iframe is created, but its old cached response is blocked by Chromium with `net::ERR_BLOCKED_BY_RESPONSE`. Full API/document readiness is false at the recorded observation. Accessing the failed native iframe yields a SecurityError. Protocol `document:opened` is recorded but is not used as proof of native readiness.

The final probe also changes only the cached native iframe response's COOP/COEP metadata, verifies its bytes remain identical, reloads the same parent, and waits for actual native readiness. This isolates cached-response policy from unrelated embed-protocol issues. The final JSON records that repair separately from the original compatibility result.

The first probe used `new=docx&embed=1` without a parent open message. That option intentionally does not create a document in embedded mode (`index.ts`). Its `framePresent:false` observation was invalid as evidence for a headers regression. Initial source and report are retained with that limitation. The corrected before-repair report is also retained.

This exposes a remaining integration gate: response policy cannot be chosen solely from SharedArrayBuffer/isolation capability. A COEP document embedded under a nonisolated ancestor may still need cached iframe response policies while its capability is false. The Worker policy configuration must account for that hosting requirement; CPU thread selection should continue using actual capability. No product behavior is changed by this diagnostic, and no fix is claimed yet.

The fixture is `.scratch/ai-csp/isolated-cold-native.docx`, generated by the preceding cold native Save verification. The browser probe and its exact result are committed; the isolated test fixture/browser profiles remain outside version control. This evaluation does not verify remote third-party documents, embed Save, model inference or physical-device behavior.

# Actual hosting isolation policy

Pages (`public/_headers`), the production static-web-server configuration (`sws.toml`), and Vite dev/preview now emit COOP same-origin and COEP require-corp. The existing cache, font MIME, and x2t Brotli contracts remain intact. No site was deployed.

21 real HEAD responses across preview, a running static-web-server 2.42.0 container mounting the production dist/config, and local Wrangler Pages verified the policy on the app, Worker, native iframe, spell engine, and x2t. A separate dev HEAD check also returned both headers. Pages uses the documented [static `_headers` contract](https://developers.cloudflare.com/pages/configuration/headers/); local checks do not prove deployed edge behavior.

For each host, independent fresh Chromium contexts covered Word, Excel, and PowerPoint native edit, native Save, file chooser reopen with exact content, and cached offline restart. The proxy forwarded actual configured headers unchanged. Offline proxy sockets were closed and all later connections refused; each offline row recorded zero upstream responses, failed uncached fetch, and isolated main/native iframe. All nine host/type combinations passed. These are native document and hosting checks, not new model quality or physical-device evidence.

The first Pages run failed: the native iframe request reported ERR_FAILED, and its precached response had redirected=true with a same-origin directory URL after Pages canonicalized index.html. Returning a followed response to navigation redirect:manual is invalid. Rebuilding only same-origin application shell and native bootstrap HTML navigation responses preserves bytes/status/headers and removes the redirect metadata. Live redirects and foreign redirected cached responses retain their semantics. Two native iframe reproduction tests failed before the first fix and passed afterwards. The next runtime run loaded Word online, but offline app navigation exposed the same redirected-response metadata on the cached editor shell. Two additional editor-shell tests reproduced that failure. All four passed after applying normalization to both explicitly identified app shell and native iframe navigation routes. Both failed runtime reports are retained alongside the successful Pages rerun.

Reproduce with `node docs/evaluations/probe-hosting-isolation-native.mjs` against preview on 5194. Set `ISOLATION_HOST_PORT=5195` or `5196` and `ISOLATION_REPORT=<report path>` for Docker or local Pages. The Pages server was started with `pnpm dlx wrangler pages dev dist --ip 127.0.0.1 --port 5196`; Docker used the exact final-image server and bind-mounted build/config, not a rebuilt application image.

Build, 116 test files / 4109 tests, root lint, and diff checks passed. Read-only review found no Important/Critical defects. Existing converter rejection-handled warnings remain.


Review identified a trailing-slash base URL boundary. A real Pages run proved `/editor/` redirected online but offline rendered the cached root shell under `/editor/`, requesting `/editor/assets/...` and rendering blank. The Worker now performs the same 308 canonicalization for exact same-origin GET navigation `/editor/`, preserving all query parameters, including dynamic document references. Two tests failed before this fix and passed after it. A subsequent Pages run covered all three document types, native Save/reopen, and offline trailing-slash entry with physical proxy refusal, canonical `/editor` path, zero upstream responses, and isolated native readiness. Both the failed slash-entry diagnostic and the successful report are retained. Reproduce with `ISOLATION_HOST_PORT=5196 ISOLATION_TRAILING_ENTRY=1 ISOLATION_REPORT=<report path> node docs/evaluations/probe-hosting-isolation-native.mjs`. Final read-only review found no Important/Critical issue in canonicalization.

# CPU public token-count client prototype

The original loaded SDK has no `countChatTokens` method: the missing-method probe terminates with the expected TypeError. The isolated client adds a public method backed by the previously verified structured native count action.

The browser probe completed successfully. ASCII, Chinese, mixed text and multi-turn requests returned 16, 25, 45 and 30 prompt tokens respectively, exactly matching actual generation usage. Repeated counts matched. A large system prompt returned 3821 against capacity 2048. Unsupported content parts raised a readable error; subsequent count and generation recovered.

The driver invokes the public method; it still instruments the private proxy solely to observe native actions. Each repeated-count interval contains only two count_chat actions. Ten successful count results are saved; the rejected request raises rather than producing a success record. Eleven count_chat calls were observed overall.

The SDK is served from the local /sdk.js endpoint. The inherited dist-route interception is unused (routeHits is empty); clientSHA256 identifies the actual locally served client. The client was generated by inserting the method and matching protocol metadata into the installed readable ESM SDK, rather than building the modified TypeScript source. The TypeScript patch is retained separately. Native artifacts are unchanged from the structured-rejection prototype.

Run `python3 docs/evaluations/verify-cpu-public-count-client.py` to verify the saved evidence and driver/native-patch hashes. The first verifier run incorrectly associated patchSHA256 with the client patch; it was corrected to the native patch actually recorded by the driver, leaving raw evidence unchanged.

This is a standalone Chromium CPU compatibility prototype, not product integration. No editor documents were modified. TypeScript build verification, template-kwargs cases, public cancellation cases, production packaging, GPU parity and full IM context budgeting remain open. Abort checks before and after counting do not interrupt native work already in flight. The deliberately short mixed-text generation is not a writing-quality acceptance test.

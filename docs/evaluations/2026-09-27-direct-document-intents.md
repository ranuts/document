# 当前文档 IM：明确意图直接执行

用户要求：IM 应能操作当前文档，而不是只声称已经操作。默认模型仍为 WebLLM 的 Qwen3-1.7B，沿用自动加载和 IndexedDB 缓存。

## 已实现

- “写到当前的文档上”：写入上一条完整回答，不重新生成。当前有选区时替换选区，否则插入当前光标位置。
- “把上一条回答替换选区”：必须存在选区，不自动退化为插入。
- “加粗”“取消加粗”：仅修改当前非空选区。
- “居中”“左对齐”“右对齐”“两端对齐”：修改当前段落或选中段落。“当前段落”明确指令存在选区时要求先取消选区，避免扩大范围。

第一阶段采用封闭的中文、英文命令语法，在模型准备状态和 API key 检查之前路由到编辑器工具。没有模型、模型正在下载也能执行这些操作。暂不支持任意自然语言排版、通过标题定位内容、整篇美化及 Excel/PPTX 格式修改；含糊范围先澄清。其他五种界面语言暂使用英文操作提示，后续需补齐本地化意图测试。

## 执行与展示

写入复用目标捕获、版本检查和正文读回验证。加粗和对齐检查只读状态、编辑器加载状态、正文区域与工具可用性，调用 SDK 后读取格式属性验证。未验证成功不会显示完成；可能已经发生的改动提示检查文档和使用撤销。

工具参数和原始 JSON 留在内部历史，界面仅展示活动摘要。澄清、错误、操作状态与可写入回答分离，刷新后仍保持区分。外部操作在模型运行期间到达时进入历史队列，避免结果覆盖；切换提供者后旧操作不会解除新会话的输入锁。

## 验证记录

新增命令解析、格式工具、直接写入、提示恢复以及并发历史测试。隔离 Chrome、新建 DOCX、禁用该测试环境 WebGPU 且无 API key：写入既有回答、加粗、取消加粗、四种对齐均读取实际 SDK 结果确认；“把全文加粗”没有修改正文或格式。该测试不操作用户正在使用的文档。

这证明已列出的确定性操作可用，不代表默认小模型的自由规划、内容生成或复杂排版能力已经改善。

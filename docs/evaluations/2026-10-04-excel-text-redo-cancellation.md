# Preserve original Excel Redo after cancelled literal text writing

The native component probe compiles current format binding, format transaction, Excel paste guard/adapter and existing preserveNativeRedo. Native fixture sets B2=30 in General or 0.00, then writes 40 and undoes it to create a real pending Redo branch.

Before opening an outer native history group, preserveNativeRedo saves that existing branch. The inner temporary-text-format transaction invokes the real native paste with its font callback deliberately delayed. Abort closes the insertion guard and paste state. The format scope restores the captured original cell format; the outer group is cancelled and ended before restoring the saved Redo branch. Ending the cancelled Excel group is necessary: bundled Excel cancelGroupPoints leaves the marker, while endGroupPoints truncates it after resetting the index. This differs from the existing PPT path and cannot be copied blindly.

After restoring and then releasing the original delayed font callback, the cell still equals its initial numeric 30 snapshot. Actual browser predicates report exact original history index, every original history point object identity, StoredData depth and no open group (_getLongPointIndex=-1). Native Redo still changes B2 to the user's original 40 with its original format; another Undo returns the exact initial 30 snapshot. Both formats pass, with no page errors. The verifier checks source hashes and every recorded condition.

This is component strategy evidence, not a production writer or IM integration. The probe operates an isolated owned history without foreign edits or document replacement. History ownership under interference, failed group opening, native blocking scope, protected/merged preflight, successful new-write branch disposal and save/reopen remain for the writer layer. No product code changed this turn, so full unit/build runs were not repeated; native probe verification, script syntax and whitespace checks were run.

# CPU prefix reuse: pre-execution diagnostic

Current WllamaProvider submits no explicit cache_prompt flag. Installed wllama 3.6.1 exposes the option in its OAI-compatible request types and forwards options as JSON to its embedded runtime. This source evidence does not establish that the bundled native backend disables caching. The current [llama.cpp server documentation](https://github.com/ggml-org/llama.cpp/blob/master/tools/server/README.md) describes common-prefix reuse and a true default, with possible backend-dependent numerical differences. Current upstream documentation is not proof of this installed WASM's default.

Before changing production, measure native browser CPU behavior for omitted, false and true cache_prompt. Use the existing identity-audited Qwen2.5 0.5B local GGUF, packaged CPU runtime and 2048 context/four threads. For each mode load a fresh engine, submit the exact same request twice, capture raw completion/usage plus wall time, then exit. Keep temperature zero, seed fixed, output budget small and prompt identical across modes. Own and close the browser; retain partial failures. Do not infer semantic correctness from repeated output equality.

Freeze the executable before execution. Record model bytes/identity, runtime/bundle hashes, original requests, native response timings and final cleanup. A warm second request is not sufficient alone to attribute a difference to caching; compare modes and available native prompt-processing counters. This is a single desktop runtime diagnostic, not randomized benchmarking, physical mobile, cancellation recovery, privacy/storage certification or default-model quality acceptance. No disk KV cache, user-visible setting or product default change.

If omitted mode already reuses the prefix, do not add an unnecessary explicit flag. If evidence remains ambiguous, investigate the pinned native backend rather than declaring caching enabled/disabled from upstream docs. Even a measured performance benefit requires cancellation/context-transition regression before product adoption.

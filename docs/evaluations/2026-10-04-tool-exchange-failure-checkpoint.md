# Preserve completed tool exchanges across inference failures

Problem: `AgentChatController.send` previously replaced its saved history with `runAgent` results only when the full loop returned. If a tool succeeded and the following inference rejected (including a context-budget rejection), the controller kept the initial user request but lost the completed call and result. A subsequent request therefore lacked evidence that the action had already happened.

The runtime now exposes an optional `onToolExchange` checkpoint after assembling the entire tool-result batch, before the next inference or cancellation return. It passes a structured clone of archival messages. The controller saves that complete history plus concurrently recorded host operations, guarded by its conversation revision. Existing successful-run history handling remains in place. There is no model retry, tool replay, confirmation card or new UI.

The new controller regression failed before implementation: saved history contained only the user request. After implementation it verifies exact call ID, input, result and saved history when the second inference fails; a subsequent request receives the complete prior exchange, with tool execution count still one. A second test holds tool execution pending, resets the conversation, then finishes execution; revision checks prevent the checkpoint from restoring cleared history. Existing controller tests for host operations, cancellation and storage pass.

Validation: product build passed; 116 test files / 4,240 tests passed. The suite emitted asynchronous rejection-handled warnings. Oxlint excluding preserved untracked `.scratch/**` diagnostic artifacts, TypeScript, Docker configuration and diff checks passed.

Scope: these are controller/runtime tests with a scripted provider and simulated tool. They do not establish real native editor rollback, browser-crash persistence, physical storage durability or guarantee that a model will never independently request the same action again. Persistence follows the user's existing history-storage setting; no opt-in preference changed. A failure inside the tool or process before the complete batch checkpoint remains outside this guarantee. Local deterministic document operations have their own direct-action history path.

## Additional cancellation and concurrency coverage

Two further controller scenarios passed after the fix. In a two-call batch, the first simulated write requests Stop during execution: it executes once, the second write is not executed, and the persisted complete result batch marks the first applied and the second `Cancelled before execution` with matching IDs. Only one inference occurs. In the other case, an external host-operation message arrives while inference after a checkpoint is pending; rejecting that inference retains both the completed tool exchange and exactly one external operation. These checks exercise orchestration and storage adapters, not physical editor writes or crash durability. The combined controller/runtime scope passed 41 tests; scoped Oxlint and TypeScript passed. No product code or UI changed in this additional coverage.

# Source-language guard controls — 2026-10-04

The current product checks a coarse script mismatch only for translation into English/German/Spanish/Portuguese. Rewrite and summarize rely on the prompt to preserve source language. The actual previous thinking experiment changed Chinese to Danish-like text; length refusal protected that particular source, but that is not a language guard.

A throwaway Python calibration assessed twelve synthetic positive/negative controls across the seven supported language families. Sources and expected verdicts are explicit in the driver/report, including names-only and quoted-slogan summaries of intentional mixed Chinese/English documents, Japanese Han-only summary and faithful Korean/Portuguese controls. These are rule controls, not actual model inference or language-detector accuracy. No new model, package or product guard was added.

At 80% source-script dominance with minimum lengths and complete disappearance of the dominant script, the rule catches the three cross-script controls and accepts the seven legitimate controls. It misses the two same-script mismatches (German→English and Spanish→Portuguese). The initial hypothesis that these particular mixed-source controls would be falsely rejected at 80% was contradicted by measurement; the documented outcome is zero false rejection at that threshold, not an invented failure.

A declared 50/60/70/80/90% threshold sweep shows that 50–60% falsely rejects both legitimate names-only and quoted English summaries; 70% falsely rejects the quoted summary; 90% additionally misses Chinese→Danish-like text containing the retained name Mira. Every threshold misses both Latin-language substitutions. The exercise does not establish all possible false negatives/positives or prove that 80% is optimal. Python Unicode-name/range counting approximates two script buckets and is not claimed byte-identical to JavaScript Unicode property escapes.

Reject this as a complete source-language acceptance solution. Do not globally block intentional mixed passages or use script conformity to claim preserved meaning. An additional conservative cross-script warning/gate might eventually be useful, but requires fresh positive controls and runtime/UI validation; it is not shipped here. A genuinely local language classifier should next be evaluated for short text, mixed passages, names/code, Chinese/Japanese separation, confidence calibration, resource/loading/offline costs and all seven languages, while preserving the existing direct edit and native Undo/Save workflow.

Run `python3 docs/evaluations/evaluate-writing-script-guard.py` to reproduce the raw report and regression checks. The report binds the driver SHA256. This evidence-only change needs no full product build/test rerun; no existing writing guards or default inference settings were changed. The larger model-semantic goal remains incomplete.

# Model loading Stop and retry

All four configured GPU models and CPU Qwen3 0.6B passed actual production IM loading Stop, followed by existing Load retry and real inference. Probe creates a native model Worker and holds initialization postMessage transport. WebLLM emits two held messages; CPU emits one. The visible existing loading Stop button invokes native terminate (GPU twice, CPU once), shows Stopped, clears model status, hides Stop and enables Load. Releasing the held message on the terminated worker does not change the stopped note or create another target model worker during the sampled interval. Retry creates a fresh model runtime and produces Hello with no visible or page errors.

This is initialization transport cancellation using already cached models. It does not establish interrupted network-download cancellation, GPU memory allocation release, arbitrary Stop timing, physical OOM, offline retry or mobile behavior. CPU uses the default local provider with navigator.gpu disabled, so the same existing local loading Stop button is exercised; the separate explicit GGUF provider Stop entry is not covered.

## 已实现的范围

实验面板（编辑器 URL 加 `?agent=1`）中，本地 WebLLM / wllama 可以勾选“修改建议”模式。默认继续使用 WebLLM + Qwen3-1.7B；模型仅生成一个 JSON 建议，应用校验后展示预览，用户点击应用才调用编辑器工具。

- DOCX：插入纯文本，存在选区时替换选区。
- XLSX：当前工作表的一个 A1 单元格，非空、无换行或制表符、无公式的值。清空单元格、范围和多步操作不支持。
- PPTX：新增只读形状文本提取工具；修改建议暂不支持。

文档身份、编辑历史、位置、编辑器交互或只读状态变化会使建议失效。取消、停止、切换 provider、重载文档和清空聊天会阻断旧建议；一次建议最多执行一次。预览使用 textContent，不解析模型 HTML，也不持久化或重放操作。

新增九条 UI 文案覆盖中文、英语、德语、西班牙语、葡萄牙语、日语、韩语；预览采用现有 ranui 亮暗主题 token。

## 真浏览器证据

使用 Chrome DevTools，在本地 Vite 服务与实际编辑器 SDK 中验证。下面的执行验证使用手工构造、经过生产解析器校验的建议，**不是模型生成的建议**。

| 场景                    | 观察结果                                                                    |
| ----------------------- | --------------------------------------------------------------------------- |
| DOCX 预览后应用         | 应用前无写入；确认后读取到 `Confirmed Word edit`；`api.Undo()` 后恢复空内容 |
| XLSX B2 写入 1250       | 应用前为空；确认后 `get_cell` 返回 `1250`；`api.asc_Undo()` 后为空          |
| DOCX 生成建议后手动编辑 | 旧建议拒绝应用；文档只有 `Manual edit`                                      |
| XLSX 移动选区           | 旧建议拒绝应用                                                              |
| XLSX 切换只读           | 旧建议拒绝应用                                                              |
| PPTX 形状读取           | 返回 `Slide 1: Reviewed PPT text`；读取前后选区类型相同                     |
| 390px 预览组件          | 亮暗模式均无横向溢出；背景/文字分别为白色/深色与深色/浅色                   |

窄屏和主题检查是独立预览组件的检查，不代表整个聊天面板所有尺寸均完成端到端测试。

## 模型测试的阻塞与限制（修复前记录）

后续配置更新：WebLLM 模型、配置与运行时缓存统一使用 SDK 的 `appConfig.cacheBackend: "indexeddb"`，缓存检测传入相同配置。旧 Cache API 数据不自动删除或迁移；此前已下载的模型首次使用新后端需要重新下载。此配置变化尚不能证明配额错误已解决，仍需真实模型加载验证。wllama 使用独立的 GGUF 缓存实现，不属于这个 WebLLM 配置。

Chrome 153、Apple M1 Pro / 16 GiB、macOS 15.5，WebLLM 0.2.85，默认 `Qwen3-1.7B-q4f16_1-MLC`。本轮三次加载均在推理前抛出 `QuotaExceededError: Quota exceeded.`。前两次编辑器页面到达 29/30 shards、约 897 MB、97%；关闭其他测试编辑器后重试，以及在独立静态页面加载，仍未成功。

计划测试包含中英文保留数字/日期/否定、选区改写、单个单元格、多步请求、删除请求与公式请求，拟各重复三次。**实际推理样本数为 0，不能给出合法计划率、语义正确率或模型到面板再到编辑器的端到端通过结论。** 缓存配额错误不计作模型能力失败；具体原因尚未确定。

因此本功能继续保持实验入口，不能宣称本地自动编辑已达到生产可用。下一次需在能够成功加载模型的环境重复这些用例，检查文本事实、拒绝不支持操作和实际面板确认流程；低质量输出保持拒绝，不通过宽松解析补救。

## 审查与验证

独立代码审查发现粘贴分隔符可能展开多个单元格，以及空字符串无法清空单元格；已在计划解析器中拒绝这两类输入，回归测试覆盖。原有工具的云端执行路径未改造为确认流程。

编辑器快照依赖当前 SDK 的历史和位置接口；接口缺失时拒绝应用。XLSX 仍使用现有粘贴接口，会按编辑器规则解释普通值，因此不保证保留单元格原格式或字符串类型。

自动化检查：全量 Vitest、TypeScript / oxlint、Docker Compose 配置检查、生产构建。具体通过数与提交见实施计划 ledger。

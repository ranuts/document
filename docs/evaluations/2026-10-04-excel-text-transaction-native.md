# Owned text-format transaction helper

Implemented `withExcelTextFormat` in `lib/agent-plugin/excel-text-transaction.ts`. It validates a current scope/original format, creates a history point and transaction, keeps @ format through awaited paste completion, and restores the captured original format in finally. A nested finally ends the transaction even if restoration fails. Scope methods must be bound to the captured cell/history and run inside an owned blocking action; the paste callback must own delayed-insertion cancellation. This helper itself does not cancel native insertion.

Ten unit cases cover completion, rejected/synchronously thrown paste, format restoration failure, initial format failure, expiration before mutation and after entering text format, unavailable original format, history point failure and settled paste cancellation. The missing-module test failed before implementation; final tests passed.

The native probe compiles this exact source with the installed TypeScript CLI, records its SHA256 and executes the compiled helper around real Excel API callbacks. Fourteen General/0.00 literal-text cases preserve exact raw/edit/display values and type, original formatting and one-step Undo/Redo. No SDK methods or return values were replaced. The original probe mistakenly supplied a string containing an uninvoked function expression, so no write occurred and the verifier rejected its result. That script/evidence is retained as `excel-text-transaction-expression-diagnostic`; the corrected probe explicitly invokes the function and its verifier checks actual callback results and source hash.

Full tests: 120 files, 4,317 tests passed. TypeScript and scoped lint passed; existing PromiseRejectionHandledWarning messages remain. This unused helper is not yet wired into set_cell, so the IM leading-zero defect remains. Native insertion cancellation/ownership, protected/merged targets, original cell binding, existing Redo preservation and save/reopen require verification before integration acceptance. Successful native cases do not prove failure-path cleanup in the actual SDK.

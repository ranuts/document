# Saved-route readonly propagation

The saved-route shortcut did not pass the parsed readonly parameter into either history-snapshot or active-source restoration. Both then used openLocalFile without a readonly option, so handleDocumentOperation defaulted to editable. This affected native editor restriction, save refusal, and consumers of the app's readonly state.

The optional readonly setting now travels from the saved URL through both recovery paths and local-file conversion. Calls that omit it, including ordinary history opens and local file-picker opens, keep their editable default. No new UI or permission prompt is added.

The first native probe incorrectly treated `isViewMode` as the readonly authority. This SDK intentionally mounts with edit permission and then applies runtime restrictions, so that flag stays false even for a correctly restricted document. That probe's initial failures are not claimed to prove this bug. The corrected probe uses the actual VIEW restriction bit (128) plus attempts at keyboard editing. The implementation was removed, the previous committed baseline rebuilt, and both real Chromium and WebKit then reproduced restriction 0 on a saved URL with readonly=1. The raw corrected red receipt is retained. The minimal propagation fix was reapplied and rebuilt; initial fixed source recovery in both engines had restriction 128 and keyboard typing did not alter text.

Full unit suite 139 files /4,501 tests, TypeScript, changed-file lint and production build pass for the propagation change. Existing PromiseRejectionHandledWarnings and repository-wide evaluation-script lint warnings are not newly claimed resolved. Independent review found no Important issue and confirmed both restoration branches retain the requested setting; omitted options reset normal editor creation to editable. The final build core is 1791158485 with vendor b6864850e7b3.

General model semantics, physical devices, OS restart and production-server deployment are outside this particular verification. This is a recovery permission fix, not an authentication or access-control boundary against someone who controls the browser and URL.

Final native acceptance: Chromium 151.0.7922.34 and WebKit 26.5 both pass active-source readonly reload, original-text preservation, actual keyboard refusal, editable reload/edit, real timed autosave (60.1 and 65.2 seconds), latest-snapshot readonly reload with the exact latest text, keyboard refusal again, and ordinary picker reopen with restriction 0 and actual EDITABLE_AGAIN typing. Both final contexts/processes close and report zero page errors. The final receipt's exact source/latest text and restriction values were independently asserted after collection. The checked-in driver adds those explicit text comparisons so future runs also reject a readonly recovery that applies the wrong revision. No snapshot injection, visibility trigger or timer mocking was used.

# Active-source storage foundation

Implemented lib/active-document-source.ts and19 behavior tests. Separate IndexedDB store; only the matching sessionStorage document id/token can read its source. Committed File references are verified before use; engines that cannot preserve them fall back to raw bytes. Replacement, explicit release, document/all deletion and24-hour idle expiry cleanup are supported. Quota, async abort, denied storage and failed byte reads resolve without throwing. No document-history DB is created by retention.

Behavioral red tests exposed an unusable committed candidate left after failed byte reading, renewal resurrecting a record removed by another tab, recovery returning already-deleted bytes, a byte fallback recreating a deleted candidate, and deletion preceding candidate creation during cleanup. Fixes clean failed candidates, conditionally renew/replace existing records, return null on observed deletion, and register before expiry cleanup yields. The first initial test run failed only because the new module did not exist; it is not claimed as a behavioral red result. Subsequent actual assertion failures establish the race/cleanup regressions.

Final full suite136 files /4,486 tests passes. Targeted19 passes; TypeScript, changed-file oxlint and diff check pass. Existing two PromiseRejectionHandledWarnings remain. Independent reviewer approved this storage scope with no remaining Critical/Important findings after three review rounds. Cross-tab cancellation follows IndexedDB registration/deletion transaction ordering, not an absolute guarantee against every operation whose JavaScript invocation began before deletion but registered afterward.

This module is not yet connected to local document open, saved-route restore, or history deletion callers. Therefore user-visible unedited-file refresh is NOT fixed by this commit. Snapshot precedence, native browser reload/offline acceptance, physical devices, large files and tab-cloning semantics remain unproved. Production build/native revalidation belongs after consuming integration; no new browser acceptance is claimed here. Existing Cache/IDB probe evidence validates primitives only, not this exact module's integrated browser behavior.

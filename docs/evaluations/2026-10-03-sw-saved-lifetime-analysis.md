# Saved-session lifetime observations

The saved Word migration gate remains false. The [full Chromium control](2026-10-03-sw-saved-full-chromium.json) reproduces the old controlling VERSION with the correct candidate installed and zero editor windows over its bounded 20-second observation. This is independent of the earlier headless-shell launch, though both installations report Chromium 151.0.7922.34. The browser channel driver launches an owned fresh browser; it does not access the user's browser state.

The [response trace](2026-10-03-sw-saved-response-trace.json) instruments ServiceWorker realms through browser CDP, reinstalling hooks when the old Worker restarts. It records 1,050 events with no trace errors. All 257 recorded waitUntil calls, 76 Cache.put calls, 124 respondWith calls and two additional unhandled-fetch observations have their corresponding settlement records. The candidate receives SKIP_WAITING. Operation keys include target and realm generation: Chromium reuses execution-context ID 1 after restart, and hook sequence numbers reset.

These are observations of recorded calls, not complete browser task accounting. Hook installation can miss early calls; the candidate's initial install waitUntil is not recorded in this run. FetchEvent.handled means response handling has completed, not that its response byte stream has fully drained or Chromium's internal idleness condition is true. Runtime prototype instrumentation and CDP attachment can affect timing. The [earlier lifetime trace](2026-10-03-sw-saved-lifetime-trace.json) predates respondWith instrumentation and intentionally has a different probe hash; it is historical evidence rather than a match to the current probe.

Current upstream Chromium [registration code](https://chromium.googlesource.com/chromium/src/+/HEAD/content/browser/service_worker/service_worker_registration.cc) checks HasNoWork during activation and includes a five-minute lame-duck fallback. The [version implementation](https://chromium.googlesource.com/chromium/src/+/HEAD/content/browser/service_worker/service_worker_version.cc) defines HasNoWork as no browser work plus renderer idleness; browser work includes in-flight requests and startup/warm-up callbacks. These HEAD sources are not pinned to the tested binary's revision. They motivate checking browser internal lifetime state, but do not establish which condition failed here or that this binary will activate at five minutes. The 20- and earlier 120-second observations cannot prove permanent failure.

An old-realm restart and another x2t WASM fetch occur around landing navigation. The landing prefetcher also fetches that resource and explicitly drains response bodies. The path alone cannot establish an orphaned converter Worker or a streaming defect. Disabling conversion caching would compromise offline behavior and is not a justified fix.

Run `python3 docs/evaluations/verify-sw-saved-lifetime.py` to check current probe hashes, unchanged old sampled text, saved-byte evidence, waiting/controller versions and balanced operation records by realm. Saved download hashes are historical observations; the verifier deliberately does not claim to verify old mutable scratch downloads after later probes overwrite them. Product source and artifact bytes are unchanged. The cause, migration fix and full acceptance remain outstanding.

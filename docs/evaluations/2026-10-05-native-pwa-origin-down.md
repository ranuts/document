# Installed PWA with serving origin unavailable

A fresh headed Chromium 151 profile installed the app from a separately owned Vite preview server on an ephemeral loopback port. The online seed opened a blank Word document so its editor resources could be cached. The browser's native PWA display preference was set to standalone. After closing the seed browser process, the probe closed that preview server and confirmed an independent Node fetch to its origin failed. The existing preview on port 5193 was not changed.

A new browser process opened the installed PWA while the serving origin remained unavailable. Browser network emulation was **not** disabled (`navigator.onLine` remained true): server shutdown, rather than an online indicator or Playwright request emulation, established origin unavailability. The app opened its cached start page in standalone mode. An explicit refresh returned HTTP 200 from its service worker. Native `PWA.launch` then opened the Word editor URL in another standalone window; the actual document engine initialized with cross-origin isolation enabled and the original blank text.

Calling the editor's native `asc_enterText` API inserted `PWA_ORIGIN_DOWN_2026`. Native Undo restored exactly `\r\n`; Redo restored exactly `PWA_ORIGIN_DOWN_2026\r\n`. These are actual editor/history operations, not a text-node replacement. No AI inference, IM command, document save/export or file reopening was tested. The installed test app was uninstalled, the final context closed, and the owned server remained closed.

The preserved first probe/result stopped at a missing main-navigation response event even though the native window displayed the cached homepage. New-page response observation can miss an initial navigation. The corrected probe explicitly refreshes the already attached native page and records that response directly, then verifies editor and history behavior. This was a harness observation failure, not evidence of an application offline failure.

This establishes installed desktop app shell plus warmed Word editor/history availability with the serving origin removed and a browser process restart. It does not certify first empty-cache use, offline AI/model availability, full network isolation (other origins and OS networking stayed available), OS reboot/shortcut launch, cache eviction, other document editors, mobile hardware or deployed hosting policies. Those requirements remain open. Native PWA methods follow the primary [Chrome DevTools PWA protocol](https://chromedevtools.github.io/devtools-protocol/tot/PWA/).

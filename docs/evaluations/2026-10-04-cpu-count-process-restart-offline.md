# Current CPU IM offline browser restart

Four actual IM runs used the current production build, an ordinary persistent Chromium profile and the product service worker. Each first loaded the current editor IM and CPU model online, closed the browser context/process, relaunched the same profile, set the browser context offline before navigation, and opened a new editor. The service worker controlled the offline page and the CPU model loaded. The recorded resource list included the exact current hashed agent plugin in both seed and offline phases.

Offline chat generated a greeting through actual native `count_chat` and `completion`. The Word edit run executed an exact multilingual cursor insertion through Operate document. Two further runs independently seeded and restarted Excel and PPT, then wrote the same marker into B2 and added a new slide text box. In all three editors, native Undo restored the initial content snapshot and Redo restored the edit. Both chat and document-operation requests invoked native count_chat before completion. No preview cards or page errors appeared. All recorded offline page requests were same-origin GETs without bodies; no remote requests were recorded. Browser `navigator.onLine` was false. Request events represent attempts/resources, not proof of network delivery; offline mode is the connectivity boundary.

The normal loader, current paired native CPU runtime, model cache and service worker were used. Only GPU capability was forced off. No inference output or request was substituted. Raw reports bind each executed driver hash. The verifier checks all four reports, readiness, current plugin resource name, offline state, actual count/generation actions and edit/history snapshots.

This proves warm-cache restart offline operation on three desktop Chromium editor CPU paths. It does not prove fresh-install offline operation, all operations within those editors, mobile/WebKit behavior, installed OS PWA launch, deployment headers, persistent-storage eviction resistance, or arbitrary instruction quality. The profile already contained vendor/model caches from earlier diagnostics; this is a warmed-profile acceptance test.

# Native installed PWA launch, scoped desktop evidence

A fresh owned persistent profile in headed Chromium 151.0.7922.34 installed the current local preview app through the browser's native `PWA.install` interface. `PWA.getOsAppState` succeeded and `PWA.launch` returned an actual page target. Setting the native app preference to standalone produced a window reporting `display-mode: standalone`; this was not a mocked media query or installability event.

After closing that browser context, a new browser process opened the same profile. Playwright offline mode was set before native PWA launch. The installed app opened its start URL in standalone mode, with `navigator.onLine=false` and an active isolation service worker. The main document returned HTTP 200 from the service worker. The test app was uninstalled through the native browser API and the final context closed normally.

The preserved first driver/result (`*-before.*`) show that installation and launch alone used browser display mode in this environment. The final driver explicitly sets the native standalone preference. Its successful result is not evidence that CDP installation selects standalone by default.

This closes the previous evidence gap for actual browser-native installation and standalone launch under simulated offline conditions. It does **not** accept the complete offline requirement: the local HTTP server stayed available, Playwright offline mode does not establish physical network isolation for all service-worker/background traffic, and recorded responses include internal fetch responses not marked as service-worker responses. No model was downloaded or inferred, no editor operation was executed, no OS shortcut/menu launch or OS reboot was tested, and Safari/physical mobile/deployed-origin behavior remains unverified. The next stronger check should remove the serving origin before installed-app restart, then verify cached model inference and native document operations in the installed window.

The install/launch/settings interface is documented in the primary [Chrome DevTools Protocol PWA domain](https://chromedevtools.github.io/devtools-protocol/tot/PWA/). Verification checks the driver hash, native API observations, standalone state, browser restart, simulated offline state, service-worker navigation response and cleanup; it does not infer model or deployment acceptance from them.

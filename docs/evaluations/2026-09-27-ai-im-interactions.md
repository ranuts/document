# AI IM 交互完善与验证

本轮沿用已确认的范围：完善现有聊天输入、消息操作和模型加载恢复，不新增模型或自动文档编辑路径。

## 改动

- 输入法组合输入期间不响应 Enter 发送；兼容 `isComposing`、composition 事件和 keyCode 229。普通 Enter 发送、Shift+Enter 换行不变。
- 用户与助手消息可复制原始纯文本；复制成功或失败会更新按钮文案。流式回复结束前隐藏复制操作。
- 错误消息可以恢复对应请求到输入框。已有草稿或正在生成时禁用恢复；不自动发送、不重放工具或文档修改。
- 新增生成等待状态、输入框与回到最新消息的可翻译无障碍标签；结束生成时关闭流式光标。等待 live region 位于消息 busy 区域之外。
- WebLLM 加载增加停止按钮；失败后清除旧进度，恢复加载按钮。配额错误显示释放站点存储或更换小模型的建议，不自动删除缓存。
- 切换 provider、模型或 key 后，旧回调不能更新新面板或覆盖持久化历史。清空会话后，迟到回复及修改建议错误不能重新填充聊天。
- 新增八条文案覆盖项目七语言；消息操作使用现有聊天主题变量，支持减少动画的系统偏好。

## 浏览器验证

Chrome DevTools，本地 Vite，390×844。使用生产 ChatView 与面板模块；下列加载错误和延迟完成通过测试替身注入，以稳定重现 UI 状态，不代表真实模型推理。

| 用例                       | 结果                                                                |
| -------------------------- | ------------------------------------------------------------------- |
| compositionstart → Enter   | 未发送                                                              |
| compositionend → Enter     | 发送一次“中文”                                                      |
| 点击恢复请求               | 请求进入输入框；发送计数不增加                                      |
| 点击复制                   | 浏览器剪贴板写入成功，按钮显示“已复制”                              |
| 亮暗聊天主题               | 文字、气泡和消息操作均渲染；暗色背景 RGB 26/26/26、文字 237/237/237 |
| 聊天和展开设置，390px      | 页面无横向溢出                                                      |
| 注入 QuotaExceededError    | 显示可操作错误，加载按钮恢复可用                                    |
| 再次点击加载               | 再次调用加载，未被旧失败锁定                                        |
| 延迟加载 → 停止 → 迟到完成 | 显示 Stopped，按钮可用，没有变为 Loaded                             |

自动化测试额外验证剪贴板拒绝、保留已有草稿、组合输入 keyCode 229、流式结束、历史清空/控制器销毁后的迟到结果、修改建议清空后的迟到错误和旧加载进度。

## 审查与限制

独立审查指出修改建议在清空后的迟到错误，以及 busy 祖先可能延迟状态播报的问题；已修复并补回归测试。控制器销毁另外阻断旧请求保存历史，保留已存的历史供新 provider 使用。

本轮没有重新评估模型质量；上一轮记录的真实模型缓存配额问题仍未解决。没有进行屏幕阅读器语音实测，不能把 DOM 无障碍检查等同于语音验证。

验证命令：`pnpm test`、`pnpm lint`、chat-ui/shared 包构建、`pnpm build`。生产构建保留现有大 chunk 提示，测试仍可能出现现有 PromiseRejectionHandledWarning。

最终结果：69 个测试文件、3,530 项测试通过；lint、包构建和生产构建通过。独立复审未发现新的重要问题。

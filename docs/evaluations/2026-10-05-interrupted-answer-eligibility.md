# Interrupted prose stays readable, not insertable

Stopping a streamed answer preserved its visible prose, but the live bubble lost its streaming class and could become the last completed answer. Persisted prose had no interruption metadata and restored with a write action. The user could therefore route a fragment through “write previous answer” or the bubble's write button.

Preserved partial strings now carry optional interrupted:true in local history. The renderer retains copy/read/context use, omits the write button and excludes interrupted rows from getLastAnswer. A status/error arriving during a live stream marks that bubble interrupted before finalizing it. Completed streams close before later activity and remain eligible. Imported interrupted assistant text blocks preserve the same protection. Validation rejects unsupported interruption values. Old string history immediately followed by host status is treated conservatively as interrupted; ambiguous hand-authored legacy adjacency may also be excluded, because those old records cannot distinguish complete from partial. No new card, confirmation, warning or model call was added.

Two new behavior tests first reproduced fragment selection as last answer and missing restored interruption state. Coverage includes live cancellation, restored strings and imported text blocks, copying, storage/context retention and completed answer behavior. Independent review identified a block-array restoration gap, now fixed with a consuming restoration→ChatView test; second review reported no remaining Important/Critical issues. Full139files/4506tests pass; existing asynchronous rejection warnings remain. Root types, scoped lint and whitespace checks pass; production build succeeds core1791165074/vendorb6864850e7b3, retaining existing chunk-size warnings. Full testing also exposed an old direct-completion copy expectation from the previous commit; its UI expectation now checks the localized completion while raw verified tool-result expectations remain unchanged.

Asking to write the previous answer invokes zero instrumented PasteHtml/InputText methods, returns an error and leaves native text unchanged. Reload and explicit Restore saved history reconstruct the exact fragment, still copyable with no write button; native document unchanged. Zero preview cards/page errors; context/browser closed.

The existing error renderer masks the specific missing-answer message with generic request failure. The corrected harness verifies actual write calls and document content instead, then reaches reload restoration. It did not require another product change. The less-specific error wording remains a UX limitation, not evidence that a fragment was written.

This establishes one real Chromium CPU interruption/restoration path and unit coverage of supported history shapes. It does not certify every browser/provider/interruption timing, OS restart, all-device performance or summary quality; the full local-AI goal remains incomplete.

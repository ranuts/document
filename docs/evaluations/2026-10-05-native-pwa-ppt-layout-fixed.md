# Native PPT margin fallback and installed offline save round trip

The previous installed-PWA PPT failure was reproduced with native geometry observations. The new 338.6667 × 190.5 mm slide contains two empty placeholders. Their recalculated lower bounds are 46.9636 and 171.5823 mm. The application preserves those objects as obstacles, adds a 3.81 mm content gap, and originally required a 5.715 mm bottom margin. Only 9.3927 mm remained below the body placeholder. The actual native text box measured 10.17 mm high after applying its existing 65% slide-width setting. Therefore the original rejection was consistent with its bounds, not an unmeasured-placeholder error.

The layout search now tries its existing 3% vertical margin first, then a 2% vertical margin only if no valid placement exists. Horizontal margins remain 3%, shape separation remains 2% of the shorter slide dimension, and the final native geometry/collision/original-object checks remain enabled. Text content, font sizing and existing placeholder geometry are not changed by this fallback. A regression based on the observed native bounds failed before the change and passes after it. Full validation: 128 files / 4409 tests, TypeScript, targeted lint, production build and read-only review passed.

A new fresh-profile headed Chromium 151 native installed-PWA run seeded the app/PPT/CPU model, closed the seed browser, removed the complete serving origin, confirmed independent fetch failure, and restarted the installed app/editor. Cached CPU loading and a greeting succeeded after manually re-entering the custom URL. Tools-mode `Add a slide` created a second slide through the native API; the exact text-box request wrote `PWA_PPT_四季_2026` on that slide. Two Undo calls restored the one-slide blank deck; two Redo calls restored the two-slide edited deck exactly. No IM errors or preview cards were observed.

Native Save's existing download fallback produced a 36,493-byte PPTX, SHA-256 `543e1a77f2f97f2a0469a1e5df2b287948947743746118b61f681e23b7823d2d`. Opening that local file through the cached homepage initialized the actual PPT engine in the installed standalone window; native slide/text snapshots matched exactly. Independent ZIP/XML checks confirm two slides, no text in slide 1 and the exact marker in slide 2. The test installation and browser contexts were cleaned up, and the owned server stayed closed.

The diagnostic driver wraps native Recalculate only to delegate and record measured bounds; it retains the failing pre-fix result. The successful post-fix driver does not use that wrapper. File System Access is deliberately unavailable to test Save's download path, not its system picker. This proves a bounded native slide/text operation and save/reopen, not arbitrary model planning, all presentation layouts, typography/render QA or multilingual semantic quality. The margin fallback still refuses content that genuinely cannot fit. Physical full-network isolation, OS reboot/shortcut launch, mobile/GPU/deployed hosting/cache eviction and automatic custom-URL restoration remain unaccepted.

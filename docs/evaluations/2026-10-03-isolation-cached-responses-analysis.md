# Isolation headers must migrate with cached responses

A fresh isolated Chromium context registered the current shipped worker, then seeded same-origin Cache API entries representing an old editor bootstrap iframe and a Worker script. The top-level control document was served with COOP same-origin and COEP require-corp. Its old cached iframe lacked isolation headers and did not expose the marker document; its old cached Worker triggered an error. The parent itself reported crossOriginIsolated true.

The test changed only response headers on those two entries, retaining the exact 25-byte iframe body and 44-byte Worker body. Cache read-back byte comparisons were true for both. After offline navigation, the cached iframe exposed the exact marker text and the cached Worker reported crossOriginIsolated true. The parent stayed isolated, navigator.onLine was false, and an uncached fetch failed. Final probe passed on Chromium 151.0.7922.34.

This establishes a concrete failure mode for changing server headers while retaining old cache-first iframe/Worker responses: body hashes alone do not capture the browser's isolation policy. The eventual acceleration change must migrate response metadata as well as configure hosting headers. It must also cover the first upgrade load under an old controlling worker and native HTTP-cached workers; this probe does not establish either behavior.

The initial control used a synthetic /assets/ Worker URL that was revalidated and replaced by the server's fallback document, making the worker result invalid. Offline emulation also reported online after navigation. That diagnostic is retained separately. The final control uses a cache-first vendor Worker URL, limits metadata updates to the two seeded entries, reapplies offline emulation after navigation, and verifies byte identity.

Exact source and worker hashes are recorded in the reports. Final probe lint and diff checks passed. No application source, server headers or service-worker behavior changed this turn. These synthetic-body checks complement the prior actual isolated Word/Excel/PPT edit, native history, Save and reopen checks; they do not replace full native cold-offline/model or header-upgrade verification. Next implementation must coordinate old cached metadata with the first isolated editor bootstrap before enabling acceleration. The overall goal remains open.

# Cached application startup after browser process restart

Both owned persistent Chromium profiles first visit the landing page online, establish the app SW and load their model in Word. The driver records the seed engine/controller/isolation, closes the complete persistent browser context, then launches a new browser process against the same profile. It reapplies only diagnostic provider/capability setup, sets the new context offline before editor navigation, opens a new Word editor, opens IM and waits for model loading. This clears the old in-process model and page state while retaining prior disk caches. The final context closes normally.

Both paths succeed: GPU Qwen3-1.7B and CPU Qwen3-0.6B load in the fresh offline process and produce new chat responses. The actual controller is `/sw.js?isolation=1` and crossOriginIsolated=true in both seed and restarted pages. Native Word text remains empty, with no recorded page/message errors or preview cards. GPU captures one actual streaming request and replies Hello. CPU replies in a stilted Dear Editor style; this is a runtime success, not greeting-quality or writing-fidelity acceptance. Its inherited GPU interceptor records no CPU request parameters.

The source and runtime header audit explain the isolation mode: vite.config.ts sets COOP same-origin and COEP require-corp for development/preview, and HEAD requests to /editor and /editor.html confirm both headers. The earlier attribution solely to inherited profile state was incomplete and the previous SW analysis is corrected. The header report is bound to the current source file SHA-256, not to every past experiment or deployed hosting configuration.

The attempt to establish a nonisolated plain SW sample is also preserved. The diagnostic replaces only the owned root app SW registration with `/sw.js`, but the page remains isolated because of the preview headers/shell policy. Both attempts stop at their explicit precondition before running model reload. They are not evidence of model or PWA failure. Achieving a genuinely nonisolated-hosting sample requires a distinct hosting configuration, rather than inferring isolation from the controller query string.

The verifier binds executed drivers to raw report SHA-256, checks fresh-process completion, offline state, seed/restarted engines, controller/isolation and complete text snapshots. It checks the failed plain-mode precondition without converting it to acceptance. No response interception overrides offline network behavior. Page request event observations are not an exhaustive transport audit; local SW cache requests may still appear as browser request events. No product code or default model changed.

Scope is cached-profile process-cold startup after online seeding on local isolated Chromium preview. It does not establish first-install offline use, cache eviction, disk integrity or download provenance, universal Safari/iOS/Android/Windows support, nonisolated hosting, saved-history restoration, writing/tool-task quality or general privacy certification. Model files and application cache contents are retained intentionally; this is not an empty-cache startup. Concurrent GPU/CPU diagnostics are not performance benchmarks. Inherited empty-document Undo/Redo snapshots are ignored.

# Safe reload guidance after CPU runtime failure

After the CPU abort handler repair, a failed inference still displayed the generic request error even though the runtime had been retired. WllamaProvider now wraps only classified RuntimeError/WllamaRuntimeError failures belonging to its current engine, after retiring that engine, with the existing safe `Local model worker failed. Reload the model to retry.` message. The original SDK error is retained as Error.cause for diagnostics. This reuses the existing exact-match presentation mapping and seven-locale reload guidance; it does not expose raw SDK details or add interface steps.

Both native RuntimeError and SDK-named WllamaRuntimeError regression cases first failed with the old raw error. They now verify the safe message plus original cause, readiness becoming false, explicit reload, one release and no replay of the failed request. Existing ordinary-error and cancellation coverage remains passing. Build, 116 test files / 4211 tests and lint passed. Independent review found no Important issue.

The actual owned Chromium CPU Qwen3-0.6B run repeats the preceding parent-side synthetic signal.abort MessageEvent during a real wllama.action request. It records one injection and one Worker terminate call, no page errors and no assistant reply. The visible error is exactly `Reload the model in settings, then try your request again.` with the existing Restore request action. Pressing Load and sending a new request produces a real Hello reply. Complete native Word text remains empty and no preview cards appear. The verifier checks this behavior and binds the report to executed driver SHA-256.

This is controlled error-shape handling during real inference, not a native Worker-emitted abort, real failed download, OOM or physical device loss. Browser observation is English only; other locale coverage comes from the existing presentation mechanism, not seven actual CPU browser runs here. Preload failures, ordinary request errors and cancellation do not enter this specific wrapper path. General privacy, offline failure recovery, devices, memory reclamation and automatic replay over arbitrary time windows are not certified. The warm owned profile has network available, service workers blocked and navigator.gpu unavailable under default webllm selection, causing CPU fallback. Empty-document Undo/Redo fields are ignored. No model default changed.

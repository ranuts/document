# Active local source recovery

User intent: local/offline document work through a simple IM, native Undo/Save, no preview/confirmation clutter. An unedited local import currently receives a saved id before any history row exists. Refreshing returns Home. Fix this without adding unedited documents to history and without replacing newer snapshots with the original source.

## Selected storage and lifetime

Use a separate IndexedDB source store and a sessionStorage pointer containing generated document id plus opaque source token. The pointer identifies only the active source for this tab. Reading another id without the matching pointer must not recover it, even if its bytes exist. Store original name/type/lastModified and raw bytes; use File-reference first only if a committed readback confirms it, otherwise fall back to bytes as the existing pending-file handoff does. The bytes-only prototype has passed actual Chromium/WebKit reload with exact SHA256 and Unicode filename. A Cache API prototype instead loses its synthetic response after WebKit reload in this app origin; do not ship that path. This does not prove every WebKit Cache API use broken or explain the loss internally.

No history docs/blobs row is created by this source store. Retain at most one source per tab; replacing it deletes the old source after the new source commits. Retain it across reload/pagehide/BFCache; those events must not delete the only recoverable source. A 24-hour idle expiration bounds reuse, with cleanup on access/open. Session pointer denial makes orphaned sources inaccessible to normal recovery; expired records must be physically pruned on subsequent store use. Do not claim precise physical deletion at tab close or at the expiry instant. Clear-history/delete-document actions must also remove matching temporary source records to avoid resurrecting explicitly forgotten data.

Snapshot precedence remains authoritative: index first restores a real saved snapshot, then attempts a matching active-tab source only if the history read succeeds and no document row exists, then follows existing URL/new/pending/expired-id behavior. A successful source restore preserves the same document id. Export, native history and editor-tool routes remain unchanged. Restoring edited documents must never silently prefer the original. Failed source writes, quota, sessionStorage denial or IndexedDB failure are best-effort and must not prevent opening/editing/saving; do not claim refresh recovery available when persistence fails.

## Implementation and checks

1. Write real source-store behavior tests with fake-indexeddb and actual File bytes: repeated reads, metadata, mismatched id/token, expiry/pruning, replacement, denied storage, abort/quota, and no history rows. Avoid string/source-code assertions. Test concurrent stale writes so an older operation cannot replace the newer tab pointer. Establish red behavior before implementation.
2. Add the bounded store module. Keep cleanup/resource handling on every success/failure/abort path; no test-only production cleanup APIs. Do not unconditionally reread huge Files if the browser can preserve a reference; memory/quota failure remains nonblocking.
3. Integrate successful local open with generated session id/source commit and integrate saved-route fallback after real snapshot recovery. Prevent a reloadable saved id from claiming a committed source before its transaction actually succeeds. Retain existing no-source fallback under storage failure. Clear the tab source after successfully opening a different source/new document, not before a failed open.
4. Integrate explicit deletion/clear-history cleanup. Test snapshot precedence and original-source fallback through the real consuming recovery path, not solely the helper.
5. Run full suite, types/lint, production build and independent review. Then real Chromium/WebKit unedited local import -> reload -> identical native text, latest edited snapshot -> reload -> latest native text, source switching/deletion, and cached-origin/offline reload. No model generation needed to certify source recovery. Repeat the explicit IM/native Save chain after source restoration if the native source tests pass.

Large-file memory, eviction/quota, multi-tab cloning, BFCache, abrupt close and browser/OS restart are distinct limits and need appropriately scoped checks. This design does not finish broad model semantic quality, AI-entry discoverability or physical device acceptance. No new UI, dependency, cloud inference or extra model download is planned.

Implementation and native evidence are recorded in [the integration receipt](../evaluations/2026-10-05-active-source-integration.md). Snapshot fallback is deliberately restricted to an absent history row after a successful read, rather than reverting original bytes after any snapshot-read failure.

# Assistant conversation craft

The user explicitly approved continuing the task-centered layout, details and purposeful-motion direction, including composer, streamed answers, provider reasoning and artifacts. They require actual screenshots and recordings before PR updates, permit incompatible presentation changes, and want component defects fixed upstream in ran.

## Observed baseline and ownership

Baseline244a9a8 has five persistent text destinations, top-level workspace h2s, a compact but administrative settings flow, a shared ChatView, explicit artifact provenance, real preparation/read/planning states and robust drafts/cancellation/review guards. Public provider reasoning is currently discarded. Installed ranui0.5 already supplies r-reasoning, disclosure-row, markdown and popover; reuse their contracts. Application layout belongs to document, reusable control defects to ran.

## Chosen design

1. **One compact header.** Remove the second five-tab row. Retain a home/Chat identity, Artifacts and Conversations as compact named/tooltip commands, then New and Close. Source management belongs beside composition; the selected-model/settings entry belongs below the composer. Primary navigation stays reachable across views. Chat is the starting view; missing configuration is an explicit preparation action, never an automatic switch into a settings form. Keep a clear return route on secondary surfaces.
2. **Composition as one object.** The draft, source context, attachment/voice controls and Send/Stop share one stable composer. A quiet model entry follows it; status/help must not form a stack of duplicate setup paragraphs. Preserve IME, multiline drafting, selection, queue/stop and actual destination disclosures. Long/localized labels reflow without truncating the editable lane.
3. **Answers as a reading surface.** User messages remain compact; assistant content has restrained typography, bounded code/table overflow and stable actions. Running, interrupted, error, review and completed states have distinct real feedback. Never simulate progress, replay a completed answer as fake tokens or let streaming drag a reader who scrolled away.
4. **Public reasoning only.** Extend the provider stream with an optional sideband callback for explicitly returned reasoning/thought-summary text. Answer text and tool arguments remain separate, including complete JSON and tool-bearing fallback responses. Gate callbacks per inference as well as per user run, so a retained callback cannot emit after its inference settles while the tool loop continues. End each phase before the first answer/tool event or settlement; Stop, supersession, conversation changes and disposal also close the presentation. ChatView renders it with ranui r-reasoning, respecting reader open/close ownership; it never participates in copy/save/apply/model context. Cap the total at 64 KiB of UTF-8 per user run, truncate only at a code point boundary, show one localized truncation notice and ignore further reasoning until the next run. Successive inference phases share that run budget. It is presentation-only, not persisted in conversation history. Unsupported providers show their real activity state and no invented reasoning block. Do not enable extra thinking requests or alter model defaults/cost policy.
5. **Artifacts as objects.** Give saved artifacts a readable preview and explicit edit state, compact title/version/mode controls, a coherent action bar and local continuation workflow. Reuse the chat package’s safe Markdown renderer for text preview so HTML and image tokens remain literal and preview cannot introduce passive remote-media requests. Installed r-markdown intentionally supports media and has no public disabling option; do not patch shadow DOM or duplicate parsers to force it into this host’s stricter source policy. Keep raw structured data behind an explicit disclosure; preserve schema validation, draft/version conflicts, native-document review, export and explicit saves. Deletion uses a nearby clear question and short confirmation/cancel actions, with focus restoration. Avoid duplicate title stacks and scattered controls.
6. **Purposeful motion.** Use existing ran fast/base roles for layer changes, reasoning/disclosure expansion and local feedback. No palette/theme interpolation, text blur or decorative motion on every token. Motion reverses cleanly; reduced motion preserves states and focus. Animate a layer's content, not an ancestor of anchored controls.

## Scope lock

Allowed: document panel/workspace/task UI and relevant styles; packages/chat-ui; narrowly scoped provider/runtime/controller reasoning sideband; product labels in all shipped locales; tests, canonical local contract and actual evidence. Upstream ran only for a reproduced reusable-component defect, on its owning implementation/tests/docs. No vendor, credentials, publishing, default model, provider trust/routing, writing approval or storage-format changes. Existing PRs stay unchanged remotely until local visual and recording acceptance passes.

## Alternatives considered

Keeping five tabs and polishing their CSS leaves configuration/content/history with equal emphasis, so rejected. Hiding all routes behind a bespoke menu adds a new control and increases routine navigation cost, so rejected. Reuse compact primary header commands and contextual composer entries instead. Rebuilding a second reasoning/disclosure primitive is rejected because ranui already owns it.

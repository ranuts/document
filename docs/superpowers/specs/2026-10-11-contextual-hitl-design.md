# 编辑器内的 AI 修改审核

## 目标与依据

用户已确认以文档成果为中心的交互方向：减少重复审核，在真实目标位置预览修改，允许继续调整，执行后能追溯与恢复，并支持键盘与读屏。

参考 Claude Artifacts 的局部选中与直接编辑、ChatGPT Canvas 的局部建议与版本恢复。参考产品提供设计依据，不意味着存在统一的 HITL UI 标准。

- https://support.claude.com/en/articles/17153992-what-are-artifacts-and-how-do-i-use-them
- https://openai.com/index/introducing-canvas/

编辑器内的差异覆盖层、目标导航和任务专属撤销是否有稳定公开 API 尚未验证。不得直接调用未验证 SDK 接口，也不得把纯文本预览称为真实排版预览。

## 交互

对话区保留一张轻量修改卡：操作摘要、真实目标、影响范围，以及必要的确认操作。输入框位置固定。无需新建常驻面板或全屏审核页面。

Word：展示被替换段落的原文与建议内容，增删差异同时使用文字标记与颜色。插入内容显示为新增，不伪造插入前正文位置。清空单独展示影响字数和原文。

Excel：展示具体工作表与范围，按单元格比较旧值、旧公式和新值。大型范围显示总数量及有限样本，明确样本不是全部内容。工具尚未支持的公式编辑不能借此新增执行能力。

PPT：展示页码和选中的文本目标、原文及新文。只有文本工具实际支持的目标可审核；不声称支持对象移动、版式修改或整份演示文稿生成。

差异默认展开，较长原文可折叠。完整内容不得因显示截断而被执行截断。若稳定 SDK 导航可用，提供“在文档中查看”；若导航会改变选区，导航后必须重新捕获和生成建议，不能沿用过期目标。

文本建议支持“编辑建议”：可编辑纯文本草稿，保存时重新运行原有计划解析和验证，生成新的一次性行动对象。数字、范围、清空等结构化工具不转换成自由文本编辑器。用户可继续用对话调整；发送调整请求时将原建议作为未执行建议提供给模型，而不是执行成功的工具结果。修改卡显示旧建议已被替代。调整模式只修改原操作的参数和内容；需要不同操作时，退出调整模式并发送新请求。

执行中可停止。成功后压缩为结果摘要和可展开的修改记录，保留真实目标与已审核的前后内容。失败或只发送成功必须使用不同状态，不能显示为已验证。

## 人工介入策略

策略由宿主判断，不能依据模型自报信心。读取不审核。覆盖、清空、修改现有公式、目标不确定或无法证实为空白的写入必须审核。

首轮继续保留现有模型生成写入的确认要求。只有已有明确指令路径、目标确认为空白、原生事务支持撤销且读回验证可靠的操作才沿用自动执行。通用模型写入的自动执行需独立通过风险策略回归后启用，不能因 UI 改版放宽默认权限。

恢复首先依赖编辑器原生撤销。没有任务历史归属验证前不增加会撤销用户后续编辑的“撤销本次”按钮。恢复按钮只有在对应历史事务仍是最新且归属已验证时启用，否则引导编辑器撤销，不能盲目回写旧快照。

## 修改范围

- lib/agent-plugin/ui/action-preview.ts：审核状态、可展开结果、编辑建议与无障碍。
- lib/agent-plugin/document-tool-action.ts、reviewed-action.ts：有界审核快照和重建后的计划验证。
- lib/agent-plugin/ui/panel.ts：建议调整上下文、一次性行动对象的生命周期。
- 新增 lib/agent-plugin/ui/change-review.ts：统一的显示模型，处理文本与表格差异，避免展示组件直接依赖 SDK。
- styles/assistant.css：沿用现有 token、r-button/r-select，窄屏与减少动画偏好。
- packages/shared/src/i18n/types.ts 及现有七个语言文件：新审核文案，沿用当前语言集合。
- 相关单元测试、agent-write-tools E2E 和审核设计文档。

不改 SDK 归档、ranui 源码、模型下载、语音、CSP、部署、依赖版本、文件解析格式、模型默认值或持久化数据库。审核记录仅保留当前会话生命周期，不持久化可执行计划。禁止提交本地路径和个人信息。

## 验收

1. Word 插入、替换、清空，Excel 单值与数字批量填充，PPT 选区替换均有准确审核目标；不支持的操作明确失败。
2. Excel 旧公式必须与显示值区分，空值不能被错误解释成读取失败；大范围读取有硬上限。
3. 编辑建议后执行的是新建议，旧建议不能再执行；解析失败保留编辑草稿并说明原因。
4. 继续调整不会把未执行建议写入已成功工具历史；新请求仍有新鲜编辑器上下文。
5. 完成记录可展开，重点击不重复执行；取消、切换编辑器、选区变化和过期守卫仍有效。
6. Tab 可达、Enter/Space 可用、编辑时 Escape 退出并恢复焦点；状态播报不重复，差异不只依赖颜色。
7. 单元验证生命周期与快照，实际浏览器验证 Word/Excel/PPT 执行、原生一次撤销与窄屏布局；运行类型检查、格式、相关 E2E 和全量单测。

## 最简替代与实施顺序

直接扩大纯文本卡不能满足 Excel 旧值和建议调整要求，因此不采用。重新实现完整 Canvas 会引入重复编辑器，因此不采用。

先实现可追溯结果和真实前后快照，再实现安全编辑建议及对话调整，最后验证稳定的编辑器目标导航和风险策略。未验证的 SDK 能力必须记录限制，不用按钮或文案伪装已实现。

## 实施结果与限制

审核比较已在对话卡内实现，并非文档排版覆盖层。Excel 使用真实工作表名和旧值/公式；新增文本框与批注的锚点单独显示，不误标为删除。完成记录无再次执行入口。

未新增目标导航和任务专属撤销：现有 Excel/PPT 定位会改变选择，Word/PPT 缺少已验证的稳定文本锚点接口，任务与原生历史归属也不足以保证撤销用户后续编辑的安全性。使用编辑器原生撤销。

可访问性覆盖语义差异、表格标题、键盘编辑与 Escape 焦点恢复、状态播报和窄屏。尚未完成真人读屏器验收。

真实默认小模型的语义分流和工具选择存在误判。明确逐字插入复用现有完整命令语法进入受约束规划；调整建议限制为原操作，已知空选区不提供替换工具。受控提供器回归证明宿主行为，不能代替真实模型质量验收。

## 视觉收敛

按用户反馈减少卡片式容器：审核建议使用对话内的开放排版，以细分隔线、文字层级和留白区分请求与建议；去掉圆角外框、整块灰底和新增内容的整段加粗。主确认使用组件库 primary 按钮，次要操作使用 text 按钮与紧凑的公开 part/token 样式。输入控件仍保留边界与焦点提示。完成记录不恢复独立卡片外框。

# 按任务选择模型的本地文档助手

## 目标与依据

用户于 2026-10-07 授权补齐按任务选择模型、编辑操作验证、写作预览应用和统一验收能力。七语言可靠生成、完整文档操作和设备离线覆盖仍是最终目标；路由实现或拒绝错误结果不能替代质量验收。

## 已核实的基础

- `packages/agent-core/src/llm/local.ts:39`：浏览器 GPU 初始化失败可回退 CPU；生成中不重放请求。
- `packages/agent-core/src/llm/writing-task.ts:60`：独立写作入口，但接收调用方给出的单个 provider；数字与文字脚本检查不能证明语义保真。
- `lib/agent-plugin/ui/panel.ts:1127`：面板调用写作入口，是任务路由接入点。
- `lib/agent-plugin/document-tool-plan.ts:95`：结构化计划解析与执行分离。
- `packages/agent-core/src/llm/ollama.ts`：通用包已有 Ollama provider；当前 ready 状态不能证明服务和模型可访问。
- 既有评估记录未证明任何候选通过全部七语言写作任务；不登记虚假的通过状态。

## 架构与行为

新增明确的任务配置，区分聊天、编辑指令、翻译、摘要和改写。翻译配置包含目标语言；配置记录引擎、模型身份和可追溯验收状态。未配置任务沿用现有默认模型并标明实验状态，用户配置不可被静默替换。不得因初始化降级而沿用原模型的质量结论。

浏览器内推理仍是默认。可选本机服务仅接受明确选择的 loopback 地址，先检查连接和模型可用性；不自动下载服务模型，不修改用户 Ollama 安装，不复用通用 provider 的远程鉴权配置。云端及局域网服务器不进入默认降级链。停止、超时和断连保留失败原因，不重放已经开始的生成或编辑。

编辑指令继续使用结构化计划、目标约束、执行后读取核对和原生撤销。明确编辑指令保持现有直接执行流程。写作输出增加原文与结果预览及显式应用；应用前检查文档、选择和原文仍一致。失败、取消或过期结果不修改文档，核对失败不声称成功。

长文档按文档结构与实际 token 预算处理，每段保留来源位置，展示未完成部分。跨段人物、否定和条件需独立验收；不得把逐段通过推导成整体语义保真。避免把源文或模型输出当作指令。

## 范围锁

允许修改 agent-core 的任务配置、provider 生命周期与本机服务适配，agent-plugin 的设置、路由、写作预览与应用，以及相关测试、七语言文案和评估工具。保持已有通用 provider API 消费者兼容；新增字段可选，旧偏好可迁移。

不修改 OnlyOffice vendor、转换器或模型二进制，不升级实验运行时，不自动启用云端，不上传文档。敏感服务配置仅用于当前会话，默认不持久化凭据。生成失败不自动改用云端。设备证据缺失需明确记录，不能以模拟代替手机实机。

## 验收

1. 路由测试覆盖五类任务、翻译语言、用户覆盖、旧配置迁移、失败与取消；真实面板显示实际任务模型。
2. 本机服务测试覆盖 schema、流式取消、连接失败、模型缺失、非 loopback 拒绝和 CSP；真实服务证据缺失不能宣称已验收。
3. 写作预览应用覆盖取消、选择变化、文档切换、重复应用、撤销重做及保存重开，分别验证 Word、Excel、PPT 支持范围。
4. 统一评估固定模型版本、量化、模板、采样、上下文和运行时。七语言分别测改写、摘要、翻译、编辑指令；包含未参与调参的新材料和跨段落案例。记录语言、责任人、数字、日期、否定、条件、完成率、延迟和资源证据。规则检查与人工语义判断分别报告。
5. 桌面 GPU、CPU、本机服务和离线重启分别验收；手机实机与其他缺失设备持续列为未完成，不扩大结论。
6. 提交前扫描用户名、本地绝对路径、凭据；模型、安装工具链和原始敏感日志保持忽略。

## 最简替代与执行顺序

复用已有 provider、编辑计划与生命周期，不引入通用 agent 框架。先实现任务配置与路由，再完成本机服务、写作预览和长文档流程，最后用统一评估决定任务默认模型。不能为了让路由测试通过而宣布模型质量达标。实施计划需列出所有新增配置消费者与迁移路径后进入产品修改。

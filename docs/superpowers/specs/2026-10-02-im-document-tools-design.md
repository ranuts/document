# IM 操作当前文档

用户追加要求：通过 IM 调用当前 Word、Excel、PPT 的 MCP 或 API 能力。沿用本地推理、离线优先、内容不上传的目标，优先使用现有编辑器 API。此次是现有工具系统的扩展，包含本地模型规划、工具执行和 IM 状态呈现。

## 已有能力与实际缺口

`tools.ts`、`office-tools.ts` 已注册读取选区/正文、插入/替换、批注、单元格读写、求和/排序、幻灯片读取/新增/复制/跳转等工具。`direct-intent.ts` 对有限中英文明确命令调用这些 API。普通本地模型聊天关闭原生工具调用；`action-plan.ts` 的审核流程仅支持 Word insert_text、Excel set_cell；PPT 被审核目标捕获拒绝。不能把注册了工具等同于模型已能可靠调用。

## 选择

采用应用侧结构化规划器和现有 API 执行器：模型只产生受约束操作，宿主校验并执行。兼容不具备原生 tools 模板的小模型。浏览器内工具经统一注册表描述能力；将来可由同一接口接入 MCP，但此次无需另起远程服务或上传文档。

直接依赖各候选原生 tools 会受模型模板与能力差异限制；新增远程 MCP 服务会增加部署/权限及数据传输，不符合当前本地目标。因此不作为首选。

## 交互与执行

1. 开始请求时绑定文档实例、编辑器类型、选区/单元格/幻灯片与版本；只向模型提供该类型可用工具。
2. 允许只读工具提供有界上下文，文档内容作为数据。工具结果不能授权后续写入；限制次数和文本长度。
3. 模型按 JSON schema 返回工具与参数。严格验证名称、类型、地址、索引、读写模式和范围；不执行模型代码或任意表达式。
4. 写操作显示预览卡片，含操作名称、目标、原内容与结果、应用/取消。读操作直接返回可解释结果。已有显式命令路径保持可用，统一展示真实执行结果。
5. 应用时再次核对文档、选区和版本；变更后预览失效。执行后由各工具实际读取/计数核验，不接受模型自称完成。
6. 停止、重试、切会话、关闭文档使旧计划失效；失败保留可恢复请求并说明原因，避免通用错误掩盖问题。

IM 明确区分正在理解、读取上下文、待审核、正在执行、已核验、失败。输入框附近展示当前目标范围，并按 Word/Excel/PPT 展示适用任务入口。消息与工具卡片统一排版，桌面/窄屏/暗色、键盘和长内容均要验证。

## 第一阶段范围

Word：读取选区/正文、生成替换或插入文本、批注、已有格式操作。
Excel：读取指定单元格/有界范围、写值、明确范围求和及排序；公式通过独立操作验证，不能混入纯值写入。
PPT：读取当前页/有界页面文本、新增/复制/跳转；文字改写必须能绑定并核验具体形状后才开放，不能伪装为已支持。

不新增删除文档、任意 JS、后台文件系统操作。多步任务拆为可说明、可核验步骤，写入由用户看到预览后执行。

## 验证与未决项

先测试结构化解析、类型能力过滤、错误参数与范围、取消/过期、读写结果核验，再用真实 Word/Excel/PPT 通过 IM 操作测试文档。每个候选模型验证工具选择、参数正确性、拒绝未知操作和内容/指令分离，不能仅检查 JSON 能解析。

当前质量实测暴露 Qwen3.5 0.8B 摘要遗漏否定、Qwen3-4B 复制指令、Qwen3-1.7B 专用改写丢姓名。现有数字守卫不证明语义正确；操作规划同样不能信任未经验证的小模型输出。三编辑器工具调用尚未完成新增统一规划/审核验收，必须与模型质量、IM 设计一起继续实施。

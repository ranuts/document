# 本地修改建议设计

用户已授权执行前一轮提出的“建议 → 预览 → 确认应用”下一阶段。本轮将其接入现有实验面板，不开放本地原生工具调用。

## 行为

- 默认仍为 WebLLM / Qwen3-1.7B，普通聊天保持现状。面板增加显式的修改建议模式。
- 每轮只接受一个白名单操作：DOCX 的 insert_text 或 XLSX 的 set_cell。拒绝未知字段、工具、错误类型、无效单元格、过长文本和多操作。
- 模型只产生计划。独立预览显示操作、目标、写入文本；应用/取消由用户选择，不自动执行。
- 捕获实际 editor API 身份、SDK history 版本与位置。生成中和等待确认时发生修改、位置变化、切文件、换 provider、停止或清空，使旧建议不可执行。
- 确认前再次检查只读状态、身份、版本及位置；计划只能消费一次。异常不重试写入。
- PPTX 先提供独立的幻灯片形状文本读取，通用 get_document_text 不再宣称支持 PPT 全文。PPT 写入计划本轮不开放，缺少稳定的目标定位与撤销验收。
- UI 沿用 ranui 和亮暗主题 token；七种界面语言提供新文案。模型输出按纯文本显示。

## 实现边界

agent-core 负责独立于编辑器的解析及生成。agent-plugin 负责 SDK snapshot、执行和预览视图。SDK 内部位置/history 适配仅针对当前固定构建；缺少能力时拒绝建议模式。
使用已有的模型实例和工作线程，不新增依赖、云请求或模型下载策略。操作结果验证、撤销及真实模型有效计划率必须分别记录，不以 mock 测试证明模型能力。

## 验收

解析拒绝危险或不完整输出；没有确认不执行；过期、取消、只读、重复应用被拒绝。
真实 DOCX/XLSX 验证计划预览、写入、内容读回、撤销与过期阻断；PPT 验证文本读取。
真实本地模型测试一组明确任务，保留失败输出，不声称规划已可靠。检查亮暗模式、窄屏及现有测试/lint/build。

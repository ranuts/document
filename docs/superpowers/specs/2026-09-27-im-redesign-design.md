# 文档助手会话界面重设计

用户反馈：现有 IM 混入工具 JSON、技术错误与下载说明，输入区的多个开关难以理解。目标是让用户直接读回答、选择任务、审阅修改，而无需理解运行时协议。

## 设计

沿用 ranui 的主题颜色、Geist 字体与现有侧栏。桌面侧栏 400px，窄屏覆盖编辑器，亮暗模式共享语义 token。顶部提供新会话、设置与关闭；使用线性 SVG 图标及本地化无障碍名称。主区采用右侧用户气泡、左侧无气泡回答，支持标题、列表、引用、代码与表格。复制回答使用小图标。输入框包含任务选择、翻译语言、引用选区与发送/停止，不再组合“建议修改”开关和任务下拉。修订模式移至设置。

任务为问答、编辑、润色、总结、翻译。问答保留现有聊天路径；本地其他任务沿用当前捕获目标、生成、人工确认、失效检测与读回验证，不能自动应用。云端任务路径不改。

参考 Desktop/deepseek-harness 的 GenericToolCard 和 ToolCallTree：用有语义的执行摘要表达工具活动，把执行详情与回答分开。只借鉴信息结构，不复制其实现。连续工具活动合并为默认折叠的原生 details；只显示产品语言，不展示名称、参数、输出或堆栈。活动表示发生过的动作，不代表执行成功。

## 展示边界

模型历史保持原始数据，展示投影另行处理。历史和实时回答移除可识别的纯工具协议 JSON 与开头的 think 区域。用户消息、普通 JSON 和代码围栏内示例保留。流式响应在开头可能是协议 JSON 或 reasoning 时暂存，识别后才输出，避免闪现。已知产品错误指导保留，未知技术错误统一为重试/设置提示。Markdown 根据 lexer token 构建 DOM，不接受模型 HTML；链接仅允许 http(s)/mailto，不自动加载图片。

模型下载与缓存说明在设置中；空会话提供配置入口。修改建议作为会话内审阅卡片，原文默认折叠，建议文本默认展开。确认、失效、停止与草稿恢复保留原有安全语义。

## 验证

先补展示边界与 Markdown 安全回归测试，再更新现有任务路由测试。浏览器检查真实编辑器、亮暗模式、窄屏、历史协议、Markdown、设置与任务选择；随后执行完整单元测试、类型/静态检查和生产构建。UI 改造不改变默认模型，也不宣称改善模型本身的能力。

## 验证中发现的兼容性补修

旧工具历史会生成正文 null 的助手消息，真实 WebLLM 问答模板拒绝请求。无活动工具时仅适配发送请求：移除 tool_calls/空正文消息，将结果转换为带明确标识的引用参考数据；保存的原始历史不变，有活动工具的请求不变。若模型只生成被过滤的协议且没有调用工具，显示恢复提示，避免空白回答。

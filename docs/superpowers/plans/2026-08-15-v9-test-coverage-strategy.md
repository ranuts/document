# v9 测试全覆盖策略：从"覆盖率百分比"到"行为矩阵零空白"

日期：2026-08-15
状态：已采纳，是 [roadmap 方向零](2026-08-15-next-phase-roadmap.md) 的执行方法论
前情：v9 刚转正，真实文档实测缺陷密集（[语料战役第 1 天](../../explorations/2026-08-15-corpus-campaign-day1-chinese-filename-bug.md)
25/25 全灭）。本文回答"这种项目怎么做到测试全覆盖"。

## 1. 先纠正目标

本项目自己写的 TS 只有约 2000 行，缺陷几乎全部落在 625 MB 的第三方引擎
以及"我们与引擎之间的集成缝隙"（文件名传递、无服务器图片注册、字体
竞态、SW 缓存态……）。**单测覆盖率从 45% 刷到 90% 对这些缺陷零帮助。**

要覆盖的不是代码行，而是**用户能碰到的行为空间**：

```
格式 × 操作 × 输入特征 × 运行环境
```

| 维度     | 取值                                                                                                                                                                                |
| -------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 格式     | docx / doc / xlsx / xls / pptx / ppt / csv / pdf                                                                                                                                    |
| 操作     | 打开、典型编辑、保存往返、导出 PDF、只读切换、插图、评论、再次打开再保存（幂等）                                                                                                    |
| 输入特征 | 文件名（非 ASCII / 空格 / 括号 / emoji / 超长）、体积（KB～60 MB）、编码（GBK CSV）、内容特性（合并单元格、冻结窗格、图表、公式、CJK 字体、页眉页脚、修订、嵌入对象、旧二进制格式） |
| 环境     | 全新 profile 冷启动 vs SW 缓存态、standalone vs embed、Docker 镜像、Chromium / WebKit / Firefox                                                                                     |

把这张矩阵显式写成表（`docs/test-matrix.md`，待建），每个格子要么有
用例，要么标"已知不覆盖"。**"全覆盖"的定义 = 这张表没有空白格。**

## 2. 语料：三层来源，都不入库

| 层  | 来源                                                                                                 | 运行时机    | 用途                                       |
| --- | ---------------------------------------------------------------------------------------------------- | ----------- | ------------------------------------------ |
| 1   | 真实私有语料（现有 `CORPUS_DIR`，本机文档）                                                          | 本地 / 夜间 | 最贴近用户                                 |
| 2   | 公开语料按需下载：Apache POI test-data、LibreOffice sc/sw/sd qa、Open XML SDK 测试文档、govdocs 抽样 | 夜间 job    | 数千份真实复杂文档，覆盖意料之外的特性组合 |
| 3   | 参数化生成的合成语料（SheetJS / docx 库按"特性开关"批量生成）                                        | 每个 PR     | 把某一类 bug 钉死成"类用例"                |

第 2 层用 curl 在 CI 夜间拉取，绝不进仓库；第 3 层沿用"页内生成、
仓库不放二进制 fixture"的现行做法。

## 3. 判据（oracle）分五层，便宜的跑 PR、贵的跑夜间

| 层                    | 判据                                                                                                                         | 成本 | 时机                              |
| --------------------- | ---------------------------------------------------------------------------------------------------------------------------- | ---- | --------------------------------- |
| L0 活性               | 无致命弹窗、无 `asc_onError`、无 unhandled rejection、无 console.error（白名单化）、加载不超时（**超时 = 失败，不是 skip**） | 极低 | 全局 fixture，挂在**所有** E2E 上 |
| L1 结构不变量         | 产物是合法 zip；sheet 数 / 段落文本 / 媒体条目数与输入一致；再打开→再保存幂等                                                | 低   | PR                                |
| L2 独立解析器交叉验证 | 用 SheetJS / mammoth / pptx 解析器分别读输入与输出，比对单元格值、文本、图片数                                               | 中   | 夜间                              |
| L3 视觉基线           | 每个语料文件打开后截图比对（Playwright `toHaveScreenshot`），抓字体乱码、图标糊等渲染回归                                    | 中   | 夜间                              |
| L4 性能预算           | 每个文件的打开 / 保存耗时上限，超出即失败（"v9 比 v7 慢"必须量化）                                                           | 低   | 夜间                              |

**L0 是性价比最高的一步**：corpus 25/25 全灭却表现为"永久转圈"，说明
现有用例把"错误已发生"和"用例通过"混在一起。全局 fixture 一挂，大量
隐性失败会立刻浮出水面。

## 4. 缺陷 → 类用例，而不是缺陷 → 实例用例

每修一个 bug 回答三个问题：

1. 这是哪一类输入 / 环境的问题？→ **参数化覆盖整类**（文件名 bug 修完，
   用例不是"某个中文名文件能打开"，而是"每种格式 × {中文, 空格, 括号,
   emoji, 200 字符} 都能打开 + 保存往返"）
2. 为什么矩阵没抓到？→ 矩阵缺了哪个维度，补维度
3. 用户怎么发现的？→ 那条路径要不要成为一个环境列（例："带旧 SW 缓存的
   老用户硬刷新前"）

维护 **escape 表**（`docs/test-matrix.md` 附录）：每个用户报出而测试
没抓到的 bug 记一行，写明"缺的维度"。矩阵空白格就从这张表长出来。

现有四条缺陷正好对号入座：

| 缺陷                                    | 缺的是什么          |
| --------------------------------------- | ------------------- |
| #1 非 ASCII 文件名 → -82 + 永久转圈     | "文件名"输入维度    |
| #2 真实 CSV 被 SheetJS 误判 HTML        | "真实 CSV"输入维度  |
| #3 打开失败遮罩不终止、无可见错误       | L0 判据             |
| #4 PPT 编辑致命弹窗（疑 SW 缓存旧构建） | "SW 缓存态"环境维度 |

## 5. 引擎是黑盒，但对引擎的依赖要有哨兵

`prepareEditorIframe` 四个守卫依赖 vendor 内部函数名 / 行为。加一类极
便宜的 **vendor 契约测试**：断言被 hook 的函数存在、签名未变、
`x2t.wasm.gz` 哈希与预期一致。下次升 vendor 是测试红，不是线上转圈。

## 6. 分级执行

| 档位    | 内容                                                                                                              |
| ------- | ----------------------------------------------------------------------------------------------------------------- |
| 每个 PR | 单测 + 合成 E2E（现有 embed-regression）+ L0 fixture + vendor 哨兵                                                |
| 每夜    | corpus（私有 + 公开下载）+ L2 交叉验证 + L3 视觉基线 + 跨浏览器 + Docker 镜像 + L4 性能预算，HTML 报告存 artifact |
| 发版前  | 全新 profile 冷启动 + 带旧 SW 缓存的升级路径 checklist                                                            |

## 7. 执行顺序（按性价比）

1. **L0 全局 fixture**：所有 E2E 自动监听致命弹窗 / `asc_onError` /
   console.error / 超时并判失败——一天内可完成，收益最大。
2. **修 P0 文件名 bug 时直接写成参数化类用例**（格式 × 文件名特征），
   顺手覆盖 #3。
3. **矩阵表落地** `docs/test-matrix.md`，把现有用例映射进去，空白格可视化。
4. **夜间 workflow** 拉公开语料跑 corpus，报告存 artifact；先拿到基线
   失败率，再按失败聚类排优先级。
5. **视觉基线与性能预算最后加**，等 L0–L2 稳定后再上，否则噪音淹没信号。

## 8. 度量指标

放弃"覆盖率百分比"，改用两个指标：

- **矩阵空白格数**——衡量"知道自己不知道"的部分；
- **escape 数**——衡量"不知道自己不知道"的部分。

两个都趋近于零，才是这类黑盒引擎项目意义上的"全覆盖"。战役通过 /
v9 release 公告解冻的判据（roadmap 方向零第 5 条）据此细化为：
矩阵无空白格 + 私有与公开语料 L0–L2 全绿 + 连续两周零 escape。

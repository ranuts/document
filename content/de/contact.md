## Einen Fehler oder eine falsch dargestellte Datei melden

**[Ein Issue auf GitHub eröffnen](https://github.com/ranuts/document/issues)** — das ist der schnellste und nützlichste Weg.

Darstellungsprobleme lassen sich mit einer Datei, die den Fehler reproduziert, sehr viel leichter beheben. Wenn das Dokument nicht vertraulich ist, macht ein Anhang (oder eine gekürzte Fassung, die das Problem noch zeigt) aus einem vagen Bericht ein lösbares Problem. Ist es doch vertraulich, beschreiben Sie stattdessen die Struktur: welches Format, ungefähre Größe, welche Funktion beteiligt ist (Tabellen, eingebettete Bilder, Pivot-Tabellen, ungewöhnliche Schriften) und was Sie erwartet gegenüber dem, was Sie gesehen haben.

Hilfreich sind außerdem:

- Das Dateiformat und ungefähr, was darin steckt
- Ihr Browser samt Version
- Was Sie getan haben, was Sie erwartet haben, was tatsächlich passiert ist
- Jeder angezeigte Fehlercode

## Zu Einbettung oder Selbst-Hosting fragen

Beides wird unterstützt und ist dokumentiert:

- **Einbettung** — die iframe- und `postMessage`-Schnittstelle steht in der [Embed-API-Referenz](/de/help/embed-api).
- **Selbst-Hosting** — das [Repository](https://github.com/ranuts/document) enthält, was Sie für eine eigene Instanz brauchen. Es steht unter AGPL-3.0, eine abgewandelte gehostete Fassung muss ihren Quellcode veröffentlichen.

Für Fragen, die keine Fehlerberichte sind, funktionieren [Issues oder GitHub Discussions](https://github.com/ranuts/document/issues) ebenfalls — mit dem Vorteil, dass die Antwort der nächsten Person mit derselben Frage hilft.

## Ein Sicherheitsproblem melden

Wenn Sie glauben, ein Sicherheitsproblem gefunden zu haben, **eröffnen Sie bitte nicht zuerst ein öffentliches Issue**. Melden Sie es vertraulich über [GitHubs Formular für Sicherheitshinweise](https://github.com/ranuts/document/security/advisories/new), damit es behoben werden kann, bevor die Details öffentlich sind.

## Wen Sie kontaktieren

Dieses Projekt wird von **ranuts** entwickelt und gepflegt — was das heißt und wie Sie es überprüfen, steht unter [Über diesen Editor](/de/about). Es ist ein persönliches Open-Source-Projekt, Antworten kommen also von einem Menschen und nicht von einem Support-Desk: Erwarten Sie eine echte Antwort, aber keine Reaktionszeit von einer Stunde.

## Was wir von Ihnen nicht brauchen

Das gehört ausdrücklich gesagt, denn Kontaktseiten sammeln sonst gern etwas ein:

- **Wir wollen Ihre Dokumente nicht.** Der Editor lädt sie nie hoch, und der Support braucht sie auch nicht — außer Sie hängen selbst eine Datei an ein Issue.
- **Es gibt kein Konto**, also nichts wiederherzustellen, zurückzusetzen oder zu löschen.
- **Es gibt keinen Newsletter.** Änderungen verfolgen Sie, indem Sie das [Repository](https://github.com/ranuts/document) beobachten; was veröffentlicht wurde, steht im [Änderungsprotokoll](/de/changelog).

## 버그나 잘못 표시되는 파일 신고

**[GitHub에 이슈 등록하기](https://github.com/ranuts/document/issues)** — 가장 빠르고 가장 도움이 되는 경로입니다.

표시 문제는 재현되는 파일 하나만 있으면 훨씬 고치기 쉽습니다. 문서가 민감하지 않다면 그 파일(또는 문제가 남아 있는 최소한으로 줄인 버전)을 첨부해 주세요. 막연한 신고가 고칠 수 있는 문제로 바뀝니다. 민감한 문서라면 대신 구조를 알려 주세요 — 어떤 형식인지, 대략 얼마나 큰지, 어떤 기능이 관련되는지(표, 삽입 이미지, 피벗 테이블, 특수 글꼴), 그리고 기대한 결과와 실제 결과입니다.

함께 적어 주시면 좋은 것:

- 파일 형식과 대략적인 내용
- 브라우저와 버전
- 무엇을 했고, 무엇을 기대했고, 실제로 무슨 일이 일어났는지
- 화면에 표시된 오류 코드

## 임베드나 자체 호스팅 문의

둘 다 지원되며 문서가 있습니다.

- **임베드** — iframe과 `postMessage` 인터페이스는 [Embed API 참고](/ko/help/embed-api)를 보세요.
- **자체 호스팅** — 직접 운영하는 데 필요한 것은 [저장소](https://github.com/ranuts/document)에 있습니다. AGPL-3.0이므로 수정해서 호스팅하는 경우 소스를 공개해야 합니다.

버그 신고가 아닌 질문도 [이슈나 GitHub Discussions](https://github.com/ranuts/document/issues)로 받습니다. 같은 궁금증을 가진 다음 사람에게 답이 남는다는 장점도 있습니다.

## 보안 문제 신고

보안 문제를 발견했다고 생각되면 **공개 이슈부터 열지 말아 주세요**. [GitHub 보안 권고 양식](https://github.com/ranuts/document/security/advisories/new)으로 비공개 신고해 주시면 세부 내용이 공개되기 전에 고칠 수 있습니다.

## 누구에게 연락하는 것인가

이 프로젝트는 **ranuts**가 개발하고 관리합니다 — 그것이 무엇을 뜻하고 어떻게 확인할 수 있는지는 [소개](/ko/about)에 있습니다. 개인 오픈소스 프로젝트이므로 답변은 지원 창구가 아니라 한 사람에게서 옵니다. 성의 있는 답은 기대하셔도 좋지만, 한 시간 이내의 응답은 어렵습니다.

## 저희가 필요로 하지 않는 것

문의 페이지는 대개 무언가를 수집하므로 분명히 적어 둡니다.

- **여러분의 문서는 필요 없습니다.** 편집기는 절대 업로드하지 않으며, 지원에도 필요하지 않습니다 — 직접 이슈에 파일을 첨부하시는 경우가 아니라면요.
- **계정이 없으므로** 복구하거나 재설정하거나 삭제할 것도 없습니다.
- **메일링 리스트도 없습니다.** 변경 사항은 [저장소](https://github.com/ranuts/document)를 watch 하면 따라갈 수 있고, 배포된 내용은 [변경 내역](/ko/changelog)에 있습니다.

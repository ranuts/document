## 报 bug 或反馈渲染不对的文件

**[在 GitHub 上提 issue](https://github.com/ranuts/document/issues)** —— 这是最快也最有用的方式。

渲染问题只要有一个能复现的文件就好修得多。如果文档不敏感，附上它（或删减到仍能复现问题的版本），就能把一个模糊的反馈变成一个可修的问题。如果文档确实敏感，那就描述结构：什么格式、大概多大、涉及什么特性（表格、内嵌图片、数据透视表、特殊字体），以及你预期看到什么、实际看到什么。

建议一并提供：

- 文件格式，以及里面大致有什么
- 浏览器及版本
- 你做了什么、预期什么、实际发生了什么
- 屏幕上出现的任何错误码

## 咨询嵌入或自建

两者都支持，也都有文档：

- **嵌入** —— 见 [Embed API 参考](/zh-CN/help/embed-api)，包含 iframe 与 `postMessage` 接口。
- **自建** —— [仓库](https://github.com/ranuts/document)里有自建所需的东西。协议是 AGPL-3.0，所以改过之后再部署，需要公开源码。

不属于 bug 的问题，同样可以[开 issue 或用 GitHub Discussions](https://github.com/ranuts/document/issues)——好处是答案会留给下一个遇到同样问题的人。

## 上报安全问题

如果你认为发现了安全问题，**请不要先开公开 issue**。请通过 [GitHub 的安全公告表单](https://github.com/ranuts/document/security/advisories/new)私下上报，以便在细节公开前先修好。

## 你联系的是谁

本项目由 **ranuts** 开发维护——[关于](/zh-CN/about)页说明了这意味着什么、以及怎么核实。这是个人开源项目，所以回复来自一个人而不是客服台：能得到真实的回答，但不要期待一小时内响应。

## 我们不需要你提供什么

值得明说，因为联系页通常都在收集东西：

- **我们不需要你的文档。** 编辑器从不上传它们，技术支持也不需要——除非你自己选择把文件附在 issue 里。
- **没有账号**，所以没有什么可找回、可重置、可删除的。
- **没有邮件列表。** 关注[仓库](https://github.com/ranuts/document)就是跟进变更的方式；[更新日志](/zh-CN/changelog)列出已发布的内容。
